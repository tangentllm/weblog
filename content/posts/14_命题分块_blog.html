一、为什么需要命题分块？

在 RAG 系统中，分块（Chunking）策略直接决定了检索质量的上限。传统的固定长度分块方式存在几个根本性问题：

  • 语义断裂 — 按字符数切割会把一个完整的概念拆散到不同块中
  • 上下文混杂 — 一个块里可能包含多个不相关的话题
  • 指代不明 — 块中的"它"、"该方法"离开了上文就无法理解
  • 粒度粗糙 — 检索时返回一整个块，但用户可能只需要其中一个事实
💡 核心洞察

如果我们能把文档拆解为原子化的、自包含的事实性陈述（即"命题"），每个命题只表达一个具体事实、独立可理解，那么检索的精度将大幅提升。

这就是 命题分块（Proposition Chunking） 的核心思想 — 用 LLM 作为"事实提取器"，将文本分解为最小粒度的知识单元。

二、什么是命题分块？

命题（Proposition）源自逻辑学，指一个可以判断真假的陈述句。在 RAG 语境下，我们将其定义为：

一条命题是文档中表达单一具体事实的陈述句，它满足三个条件：
① 原子性 — 只包含一个事实
② 自包含 — 脱离上下文也能独立理解
③ 全称化 — 用完整名称替代代词和缩写

一个直观的例子

📄 原文
人工智能（AI）是一门研究如何让计算机模拟人类智能行为的科学。1956年，达特茅斯会议被认为是人工智能研究的起点。
✅ 生成的命题
命题 1：人工智能（AI）是一门研究如何让计算机模拟人类智能行为的科学。
命题 2：1956年，达特茅斯会议被认为是人工智能研究的起点。

注意命题 2 中，如果原文是"它被认为是AI研究的起点"，命题化后会替换为完整的"人工智能"，确保独立可理解。

三、传统分块 vs 命题分块

❌ 传统字符分块

  • 按固定字符数（如 500 字符）切割
  • 一句话可能被拦腰截断
  • 一个块混杂多个话题
  • 代词"它"指向不明
  • 检索粒度 = 块大小

✅ 命题分块

  • 按事实语义边界拆解
  • 每条命题是一个完整陈述
  • 每条命题只表达一个事实
  • 全称替换，独立可理解
  • 检索粒度 = 单个事实

下面逐步拆解核心实现。

五、Step 1 — 从文本块生成命题

首先用 PyPDF2 提取 PDF 文本，然后用 RecursiveCharacterTextSplitter 进行重叠分块（800 字符，100 字符重叠），得到 39 个文本块。接着，用 GPT-4o 将每个块拆解为命题列表：

from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

def generate_propositions(chunk: str, llm: ChatOpenAI) -> list[str]:
    """用 LLM 从文本块中生成原子化命题列表。"""
    prompt = ChatPromptTemplate.from_messages([
        ("system", """你是一个将文本拆解为原子化命题的专家。

规则：
1. 每条命题只表达一个具体事实
2. 每条命题必须独立可理解（用全称替代代词）
3. 保留关键数字、日期、名称
4. 不要添加原文没有的信息
5. 以 JSON 数组格式返回命题列表"""),
        ("human", "请将以下文本拆解为命题列表：\n\n{text}")
    ])
    chain = prompt | llm
    response = chain.invoke({"text": chunk})
    # 解析 JSON 数组
    import json
    propositions = json.loads(response.content)
    return propositions
✅ Prompt 设计要点

系统提示中明确了 5 条规则，其中最关键的是"用全称替代代词" — 这确保每条命题脱离上下文后仍然可理解。例如"它改变了NLP"会被改写为"Transformer 改变了 NLP"。

六、Step 2 — 质量评估与过滤

LLM 生成的命题质量参差不齐，需要严格的质量把关。我们设计了一个四维度评分机制：

维度 评估内容 满分
准确性（Accuracy） 命题是否忠实于原文，无捏造或歪曲 10
清晰度（Clarity） 命题是否表述清晰、无歧义 10
完整性（Completeness） 命题是否包含足够信息，不遗漏关键细节 10
简洁性（Conciseness） 命题是否精炼，无冗余表达 10 
def evaluate_proposition(proposition: str, original_text: str,
                         llm: ChatOpenAI) -> dict:
    """对单条命题进行四维度质量评估，返回评分字典。"""
    prompt = ChatPromptTemplate.from_messages([
        ("system", """你是一个命题质量评审员。请从四个维度打分（1-10）：
- accuracy: 是否忠实于原文
- clarity: 是否表述清晰无歧义
- completeness: 是否包含足够信息
- conciseness: 是否精炼无冗余

以 JSON 格式返回：{"accuracy": N, "clarity": N, "completeness": N, "conciseness": N}"""),
        ("human", "原文：\n{text}\n\n待评估命题：{prop}")
    ])
    chain = prompt | llm
    response = chain.invoke({"text": original_text, "prop": proposition})
    import json
    scores = json.loads(response.content)
    return scores

def passes_quality_check(scores: dict, threshold: int = 7) -> bool:
    """所有维度均 >= threshold 才通过。"""
    return all(v >= threshold for v in scores.values())
⚠️ 质量过滤的效果

在实验中，1425 条命题里有大量未通过质量检查。典型失败案例如：

七、Step 3 — 构建双级向量存储

为了对比检索效果，我们同时构建两个向量存储：

from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings

def build_vector_stores(chunks: list[str],
                        propositions: list[str]):
    """分别构建块级和命题级向量存储。"""
    embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

    # 块级向量存储 — 传统方式
    chunk_store = FAISS.from_texts(chunks, embeddings)

    # 命题级向量存储 — 命题分块方式
    prop_store = FAISS.from_texts(propositions, embeddings)

    return chunk_store, prop_store
💡 为什么需要双级存储？

命题级存储提供精准检索（命中具体事实），块级存储保留上下文完整性。在实际应用中，可以采用"先命题定位，再回溯块上下文"的混合策略。

八、Step 4 — 检索效果对比

def compare_retrieval_approaches(query: str,
                                  chunk_store: FAISS,
                                  prop_store: FAISS,
                                  k: int = 5):
    """对比两种检索方式对同一查询的返回结果。"""
    # 块级检索
    chunk_results = chunk_store.similarity_search(query, k=k)
    print("=" * 60)
    print(f"📦 块级检索 (top-{k})")
    print("=" * 60)
    for i, doc in enumerate(chunk_results, 1):
        print(f"\n[块 {i}] (长度: {len(doc.page_content)} 字符)")
        print(doc.page_content[:300] + "...")

    # 命题级检索
    prop_results = prop_store.similarity_search(query, k=k)
    print("\n" + "=" * 60)
    print(f"🎯 命题级检索 (top-{k})")
    print("=" * 60)
    for i, doc in enumerate(prop_results, 1):
        print(f"\n[命题 {i}] (长度: {len(doc.page_content)} 字符)")
        print(doc.page_content)

    return chunk_results, prop_results

完整处理管道

def process_document_into_propitions(pdf_path: str) -> tuple:
    """完整管道：PDF → 分块 → 命题生成 → 质量过滤 → 向量存储。"""
    from PyPDF2 import PdfReader
    from langchain.text_splitter import RecursiveCharacterTextSplitter

    # 1. 提取文本
    reader = PdfReader(pdf_path)
    text = ""
    for page in reader.pages:
        text += page.extract_text() or ""

    # 2. 重叠分块
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=800,
        chunk_overlap=100
    )
    chunks = splitter.split_text(text)
    print(f"📦 文档被切分为 {len(chunks)} 个块")

    # 3. 生成命题
    llm = ChatOpenAI(model="gpt-4o", temperature=0)
    all_propositions = []
    for i, chunk in enumerate(chunks):
        props = generate_propositions(chunk, llm)
        all_propositions.extend(props)
        print(f"  块 {i+1}/{len(chunks)}: 生成 {len(props)} 条命题")
    print(f"📋 共生成 {len(all_propositions)} 条命题")

    # 4. 质量过滤
    passed = []
    for prop in all_propositions:
        scores = evaluate_proposition(prop, text, llm)
        if passes_quality_check(scores):
            passed.append(prop)
    print(f"✅ 质量过滤后保留 {len(passed)} 条命题")

    # 5. 构建向量存储
    chunk_store, prop_store = build_vector_stores(chunks, passed)
    return chunks, passed, chunk_store, prop_store

十、权衡与最佳实践

命题分块的优势

  • 检索粒度细化到单个事实级别
  • 每条结果自包含，无需额外上下文拼接
  • 特别适合事实密集型文档（论文、报告、百科）
  • 可以追溯到原始块获取完整上下文

命题分块的代价

  • LLM 调用成本高 — 39 个块 + 1425 次质量评估 = 大量 API 调用
  • 处理时间长 — 命题生成和质量评估都需要 LLM 推理
  • 命题膨胀 — 39 块膨胀到 1425 条命题（36 倍），存储开销增大
  • 质量不稳定 — LLM 生成的命题质量参差不齐，需要严格过滤

最佳实践建议

🎯 何时使用命题分块？
  • ✅ 文档以事实陈述为主（百科、产品手册、FAQ）
  • ✅ 对检索精准度要求极高（医疗、法律、金融）
  • ✅ 文档量可控，可以承受离线处理的成本
  • ❌ 不适合叙事性/文学性文本（小说、故事）
  • ❌ 不适合需要实时处理的场景

十一、总结

命题分块代表了 RAG 分块策略从"按字符切割"到"按语义拆解"的质变。通过 LLM 将文档分解为原子化的事实陈述，我们实现了：

  1. 更精准的检索 — 直接命中具体事实，而非在长块中搜索
  2. 更干净的上下文 — 每条结果自包含、无噪音
  3. 更可靠的生成 — LLM 基于精准事实生成回答，减少幻觉

当然，这种精度提升是以处理成本和存储开销为代价的。在实际项目中，建议根据文档类型和精度需求灵活选择分块策略，甚至可以混合使用 — 用块级检索获取上下文范围，用命题级检索定位具体事实。
