一、为什么需要多模态 RAG？

传统 RAG 系统只处理文本。然而现实中的文档——论文、报告、教科书——往往包含大量图表、示意图、表格，这些视觉元素承载着不可替代的信息。

想象一下：你正在检索一篇机器学习论文，问「Transformer base model 的 BLEU 分数是多少？」如果这个数值恰好出现在一张表格图片中，纯文本 RAG 将完全无法触及它。

核心思路

多模态 RAG 的解决方案很优雅：用视觉模型为每张图像生成一段文字描述（caption），然后将这些描述和文本块一起嵌入到同一个向量空间中。检索时，文本和图像描述统一参与相似度匹配。

这样做的好处：

  • 解锁图表和示意图中「锁定」的信息
  • 理解补充文本的表格和数据可视化
  • 构建更全面的知识库，覆盖文档的所有模态
  • 回答依赖视觉数据的问题

四、第一步 —— 从 PDF 提取文本和图像

我们使用 PyMuPDF（即 fitz）逐页遍历 PDF，分别提取文本内容和嵌入的图像。每一页的文本保存为字典，图像则写入磁盘并记录元数据。

def extract_content_from_pdf(pdf_path, output_dir=None):
    """
    从 PDF 文件中提取文本和图像。

    参数:
        pdf_path (str): PDF 文件路径
        output_dir (str, optional): 图像保存目录

    返回:
        Tuple[List[Dict], List[Dict]]: 文本数据, 图像数据
    """
    temp_dir = None
    if output_dir is None:
        temp_dir = tempfile.mkdtemp()
        output_dir = temp_dir
    else:
        os.makedirs(output_dir, exist_ok=True)

    text_data = []
    image_paths = []

    print(f"Extracting content from {pdf_path}...")

    try:
        with fitz.open(pdf_path) as pdf_file:
            for page_number in range(len(pdf_file)):
                page = pdf_file[page_number]

                # ---- 提取文本 ----
                text = page.get_text().strip()
                if text:
                    text_data.append({
                        "content": text,
                        "metadata": {
                            "source": pdf_path,
                            "page": page_number + 1,
                            "type": "text"
                        }
                    })

                # ---- 提取图像 ----
                image_list = page.get_images(full=True)
                for img_index, img in enumerate(image_list):
                    xref = img[0]
                    base_image = pdf_file.extract_image(xref)

                    if base_image:
                        image_bytes = base_image["image"]
                        image_ext = base_image["ext"]

                        img_filename = (
                            f"page_{page_number+1}"
                            f"_img_{img_index+1}.{image_ext}"
                        )
                        img_path = os.path.join(output_dir, img_filename)

                        with open(img_path, "wb") as img_file:
                            img_file.write(image_bytes)

                        image_paths.append({
                            "path": img_path,
                            "metadata": {
                                "source": pdf_path,
                                "page": page_number + 1,
                                "image_index": img_index + 1,
                                "type": "image"
                            }
                        })

        print(f"Extracted {len(text_data)} text segments "
              f"and {len(image_paths)} images")
        return text_data, image_paths

    except Exception as e:
        print(f"Error extracting content: {e}")
        if temp_dir and os.path.exists(temp_dir):
            shutil.rmtree(temp_dir)
        raise
💡 关键细节

page.get_images(full=True) 会提取页面中所有引用的图像（包括共享的图像），extract_image(xref) 返回的字典包含 image（原始字节）和 ext（格式后缀如 png / jpeg）。元数据中用 "type" 字段区分文本和图像，后续检索时据此分类结果。

五、第二步 —— 文本分块

文本分块策略沿用经典的固定大小 + 滑动窗口重叠方案。每个块 1000 字符，相邻块重叠 200 字符，确保语义不会在边界处被截断。

def chunk_text(text_data, chunk_size=1000, overlap=200):
    """
    将文本数据分割为重叠的块。

    参数:
        text_data (List[Dict]): 从 PDF 提取的文本数据
        chunk_size (int): 每块字符数
        overlap (int): 块间重叠字符数

    返回:
        List[Dict]: 分块后的文本数据
    """
    chunked_data = []

    for item in text_data:
        text = item["content"]
        metadata = item["metadata"]

        # 短文本直接保留
        if len(text) < chunk_size / 2:
            chunked_data.append({"content": text, "metadata": metadata})
            continue

        # 滑动窗口分块
        chunks = []
        for i in range(0, len(text), chunk_size - overlap):
            chunk = text[i:i + chunk_size]
            if chunk:
                chunks.append(chunk)

        for i, chunk in enumerate(chunks):
            chunk_metadata = metadata.copy()
            chunk_metadata["chunk_index"] = i
            chunk_metadata["chunk_count"] = len(chunks)

            chunked_data.append({
                "content": chunk,
                "metadata": chunk_metadata
            })

    print(f"Created {len(chunked_data)} text chunks")
    return chunked_data
为什么 overlap=200？

重叠区域确保跨越块边界的句子不会被割裂。1000 字符约 200-250 个英文单词，200 字符的重叠约覆盖 1-2 句话，在语义完整性和冗余之间取得平衡。

六、第三步 —— 用视觉模型生成图像描述

这是多模态 RAG 的核心创新点。我们将每张图像发送给视觉大模型 LLaVA-1.5-7B，让它生成一段详细的文字描述。这段描述将代替图像本身参与后续的文本嵌入和检索。

6.1 图像 Base64 编码

def encode_image(image_path):
    """将图像文件编码为 base64 字符串。"""
    with open(image_path, "rb") as image_file:
        encoded_image = base64.b64encode(image_file.read())
        return encoded_image.decode('utf-8')

6.2 调用 LLaVA 生成描述

def generate_image_caption(image_path):
    """
    使用视觉模型为图像生成文字描述。

    参数:
        image_path (str): 图像文件路径

    返回:
        str: 生成的图像描述
    """
    if not os.path.exists(image_path):
        return "Error: Image file not found"

    try:
        Image.open(image_path)  # 验证图像有效性
        base64_image = encode_image(image_path)

        response = client.chat.completions.create(
            model="llava-hf/llava-1.5-7b-hf",
            messages=[
                {
                    "role": "system",
                    "content": (
                        "You are an assistant specialized in "
                        "describing images from academic papers. "
                        "Provide detailed captions that capture key "
                        "information. If the image contains charts, "
                        "tables, or diagrams, describe their content "
                        "and purpose clearly. Your caption should be "
                        "optimized for future retrieval when people "
                        "ask questions about this content."
                    )
                },
                {
                    "role": "user",
                    "content": [
                        {
                            "type": "text",
                            "text": "Describe this image in detail, "
                                    "focusing on its academic content:"
                        },
                        {
                            "type": "image_url",
                            "image_url": {
                                "url": f"data:image/jpeg;base64,"
                                       f"{base64_image}"
                            }
                        }
                    ]
                }
            ],
            max_tokens=300
        )

        caption = response.choices[0].message.content
        return caption

    except Exception as e:
        return f"Error generating caption: {str(e)}"
💡 Prompt 工程要点

注意 system prompt 的关键指令：「Your caption should be optimized for future retrieval」。这不是让模型随意描述图像，而是专门为后续的嵌入检索优化描述内容。模型会倾向于提取关键数据点和语义信息，而非泛泛而谈。

6.3 批量处理所有图像

def process_images(image_paths):
    """
    批量处理所有图像，为每张生成描述。

    参数:
        image_paths (List[Dict]): 提取的图像路径列表

    返回:
        List[Dict]: 带有描述的图像数据
    """
    image_data = []
    print(f"Generating captions for {len(image_paths)} images...")

    for i, img_item in enumerate(image_paths):
        print(f"Processing image {i+1}/{len(image_paths)}...")
        img_path = img_item["path"]
        metadata = img_item["metadata"]

        caption = generate_image_caption(img_path)

        image_data.append({
            "content": caption,        # 生成的描述
            "metadata": metadata,       # 原始元数据
            "image_path": img_path      # 图像路径（可溯源）
        })

    return image_data
⚠️ 图像处理注意事项

LLaVA-1.5-7B 是一个 70 亿参数的视觉语言模型，推理时需要 GPU 支持。如果使用 API 方式调用（如通过 OpenAI 兼容接口），需确认服务端已部署该模型。对于本地部署，建议至少 16GB 显存。

七、第四步 —— 统一嵌入与向量存储

文本块和图像描述现在都是字符串。我们用同一个嵌入模型 text-embedding-ada-002 将它们映射到同一个向量空间。这就是多模态 RAG 的精髓——通过文字描述将视觉信息「翻译」成文本，从而复用成熟的文本嵌入基础设施。

7.1 创建嵌入

def create_embeddings(texts, model="text-embedding-ada-002"):
    """
    为文本列表创建嵌入向量。

    参数:
        texts (List[str]): 输入文本列表
        model (str): 嵌入模型名称

    返回:
        List[List[float]]: 嵌入向量列表
    """
    if not texts:
        return []

    batch_size = 100
    all_embeddings = []

    for i in range(0, len(texts), batch_size):
        batch = texts[i:i + batch_size]
        response = client.embeddings.create(
            model=model,
            input=batch
        )
        batch_embeddings = [item.embedding for item in response.data]
        all_embeddings.extend(batch_embeddings)

    return all_embeddings

7.2 MultiModalVectorStore 实现

class MultiModalVectorStore:
    """多模态内容向量存储（基于余弦相似度）。"""

    def __init__(self):
        self.vectors = []
        self.contents = []
        self.metadata = []

    def add_item(self, content, embedding, metadata=None):
        self.vectors.append(np.array(embedding))
        self.contents.append(content)
        self.metadata.append(metadata or {})

    def add_items(self, items, embeddings):
        for item, embedding in zip(items, embeddings):
            self.add_item(
                content=item["content"],
                embedding=embedding,
                metadata=item.get("metadata", {})
            )

    def similarity_search(self, query_embedding, k=5):
        """余弦相似度检索，返回 Top-K 结果。"""
        if not self.vectors:
            return []

        query_vector = np.array(query_embedding)

        similarities = []
        for i, vector in enumerate(self.vectors):
            similarity = np.dot(query_vector, vector) / (
                np.linalg.norm(query_vector)
                * np.linalg.norm(vector)
            )
            similarities.append((i, similarity))

        similarities.sort(key=lambda x: x[1], reverse=True)

        results = []
        for i in range(min(k, len(similarities))):
            idx, score = similarities[i]
            results.append({
                "content": self.contents[idx],
                "metadata": self.metadata[idx],
                "similarity": float(score)
            })

        return results

7.3 完整处理管道

def process_document(pdf_path, chunk_size=1000, chunk_overlap=200):
    """
    端到端处理文档，构建多模态向量存储。

    返回:
        Tuple[MultiModalVectorStore, Dict]: 向量存储 + 文档信息
    """
    image_dir = "extracted_images"
    os.makedirs(image_dir, exist_ok=True)

    # 1. 提取
    text_data, image_paths = extract_content_from_pdf(
        pdf_path, image_dir
    )

    # 2. 文本分块
    chunked_text = chunk_text(text_data, chunk_size, chunk_overlap)

    # 3. 图像描述
    image_data = process_images(image_paths)

    # 4. 合并 → 嵌入 → 存储
    all_items = chunked_text + image_data
    contents = [item["content"] for item in all_items]

    print("Creating embeddings for all content...")
    embeddings = create_embeddings(contents)

    vector_store = MultiModalVectorStore()
    vector_store.add_items(all_items, embeddings)

    doc_info = {
        "text_count": len(chunked_text),    # 56
        "image_count": len(image_data),      # 3
        "total_items": len(all_items),       # 59
    }

    print(f"Added {len(all_items)} items to vector store "
          f"({len(chunked_text)} text chunks, "
          f"{len(image_data)} image captions)")

    return vector_store, doc_info

八、第五步 —— 多模态检索与生成

查询阶段与标准 RAG 无异：将用户问题嵌入，在向量库中做余弦相似度检索，取回 Top-K 结果后交给 LLM 生成答案。唯一区别是检索结果中可能同时包含文本块和图像描述。

def query_multimodal_rag(query, vector_store, k=5):
    """
    查询多模态 RAG 系统。

    参数:
        query (str): 用户查询
        vector_store (MultiModalVectorStore): 向量存储
        k (int): 检索结果数

    返回:
        Dict: 查询结果和生成的回复
    """
    print(f"\n=== Processing query: {query} ===\n")

    # 查询嵌入
    query_embedding = create_embeddings(query)

    # 相似度检索
    results = vector_store.similarity_search(query_embedding, k=k)

    # 按类型分类结果
    text_results = [
        r for r in results if r["metadata"].get("type") == "text"
    ]
    image_results = [
        r for r in results if r["metadata"].get("type") == "image"
    ]

    print(f"Retrieved {len(results)} relevant items "
          f"({len(text_results)} text, "
          f"{len(image_results)} image captions)")

    # 生成回复
    response = generate_response(query, results)

    return {
        "query": query,
        "results": results,
        "response": response,
        "text_results_count": len(text_results),
        "image_results_count": len(image_results)
    }

回复生成

def generate_response(query, results):
    """根据检索结果生成回复。"""
    context = ""
    for i, result in enumerate(results):
        content_type = (
            "Text" if result["metadata"].get("type") == "text"
            else "Image caption"
        )
        page_num = result["metadata"].get("page", "unknown")

        context += f"[{content_type} from page {page_num}]\n"
        context += result["content"]
        context += "\n\n"

    system_message = (
        "You are an AI assistant specializing in answering "
        "questions about documents that contain both text and "
        "images. Use the retrieved text passages and image "
        "captions to provide a comprehensive response. "
        "If information comes from an image or chart, "
        "mention this in your answer."
    )

    response = client.chat.completions.create(
        model="gpt-3.5-turbo",
        messages=[
            {"role": "system", "content": system_message},
            {"role": "user", "content": (
                f"Query: {query}\n\n"
                f"Retrieved content:\n{context}\n"
                f"Please answer the query based on the "
                f"retrieved content."
            )}
        ],
        temperature=0.1
    )

    return response.choices[0].message.content

九、多模态 vs 纯文本 RAG 架构对比

为了理解多模态 RAG 的优劣，我们实现了一个纯文本 RAG 作为对照组。两者的唯一区别在于：多模态版本在向量库中额外包含了图像描述。

对照组：纯文本向量存储

def build_text_only_store(pdf_path,
                          chunk_size=1000,
                          chunk_overlap=200):
    """构建仅包含文本的向量存储（对照组）。"""
    text_data, _ = extract_content_from_pdf(pdf_path, None)
    chunked_text = chunk_text(text_data, chunk_size, chunk_overlap)

    contents = [item["content"] for item in chunked_text]
    print("Creating embeddings for text-only content...")
    embeddings = create_embeddings(contents)

    vector_store = MultiModalVectorStore()
    vector_store.add_items(chunked_text, embeddings)

    print(f"Added {len(chunked_text)} text items "
          f"to text-only vector store")
    return vector_store

评估框架

我们使用 LLM-as-Judge 的方式，让 GPT-3.5-Turbo 充当评估者，从准确性、完整性、相关性和视觉信息利用四个维度对比两种方案的回答质量。

def evaluate_multimodal_vs_textonly(pdf_path, test_queries,
                                     reference_answers=None):
    """比较多模态 RAG 与纯文本 RAG。"""
    print("=== EVALUATING MULTI-MODAL RAG VS TEXT-ONLY RAG ===\n")

    # 构建两种向量存储
    mm_vector_store, mm_doc_info = process_document(pdf_path)
    text_vector_store = build_text_only_store(pdf_path)

    results = []
    for i, query in enumerate(test_queries):
        print(f"\n=== Evaluating Query {i+1}: {query} ===")

        reference = (reference_answers[i]
                     if reference_answers and i < len(reference_answers)
                     else None)

        # 分别运行两种 RAG
        mm_result = query_multimodal_rag(query, mm_vector_store)
        text_result = query_multimodal_rag(query, text_vector_store)

        # LLM-as-Judge 对比
        comparison = compare_responses(
            query,
            mm_result["response"],
            text_result["response"],
            reference
        )

        results.append({
            "query": query,
            "multimodal_response": mm_result["response"],
            "textonly_response": text_result["response"],
            "multimodal_results": {
                "text_count": mm_result["text_results_count"],
                "image_count": mm_result["image_results_count"]
            },
            "reference_answer": reference,
            "comparison": comparison
        })

    overall_analysis = generate_overall_analysis(results)

    return {
        "results": results,
        "overall_analysis": overall_analysis,
        "multimodal_doc_info": mm_doc_info
    }

💡 多模态 RAG 的真正舞台

多模态 RAG 的优势在以下场景中才会显现：

  • 查询涉及图表中的具体数据（如「Figure 3 中的准确率曲线」）
  • 文档以视觉信息为主（如产品手册中的装配图）
  • 表格以图片形式嵌入 PDF（无法直接提取为文本）
  • 需要理解架构图、流程图的语义

十一、总结与展望

本篇核心收获

📌 关键要点
  1. 图像 → 文字描述 → 嵌入：多模态 RAG 的核心思路是将视觉信息「翻译」成文本，复用文本嵌入基础设施
  2. LLaVA-1.5-7B 作为视觉模型，能为学术论文中的图表生成高质量的描述
  3. 统一向量空间：文本块和图像描述使用同一个嵌入模型（ada-002），在同一个向量库中统一检索
  4. 适用场景很重要：当答案在文本中时，纯文本 RAG 更高效；当答案在图表中时，多模态 RAG 不可替代

改进方向

  • 直接图像嵌入：使用 CLIP 等模型直接嵌入图像（而非先生成描述），可保留更丰富的视觉信息
  • 更强的视觉模型：GPT-4V、Gemini Pro Vision 等可生成更精确的图像描述
  • 混合检索策略：文本和图像分别检索后融合结果（第 16 篇「融合检索」将深入探讨）
  • 表格专项处理：使用专门的表格识别模型（如 Table Transformer）提升表格信息的提取质量
