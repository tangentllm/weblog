Generative Agents：给每个 Agent 一套"记忆—反思—规划"系统

这篇 2023 年的经典工作为什么至今仍在影响 Multi-Agent、Memory Agent 与 AI 社会模拟？答案不是"让 LLM 更像人"，而是让 Agent 拥有一套能长期积累经验、提炼认知并驱动下一步行为的架构。

Joon Sung Park · Joseph C. O'Brien · Carrie J. Cai · Meredith Ringel Morris · Percy Liang · Michael S. Bernstein
arXiv:2304.03442 · UIST 2023
SECTION 01

引言：一个 Agent，为什么会"活不久"？

早期的大模型 Agent 很容易给人一种"聪明但健忘"的感觉：它能够围绕当前输入生成一段合理回答，却很难在数小时、数天甚至更长时间里保持稳定的人格、关系与目标。传统游戏 NPC 则恰恰相反——状态稳定，但大量行为需要工程师提前写死。论文 Generative Agents: Interactive Simulacra of Human Behavior 把两条路线接了起来：让大语言模型负责开放式语言推理，再用计算架构管理长期记忆、反思和规划。

作者在一个名为 Smallville 的沙盒环境里放入 25 个 Agent。每个 Agent 都有职业、家庭、兴趣与生活安排，会做饭、上班、聊天、形成关系，还会记住过去发生的事情，并据此安排未来。更令人印象深刻的是：只需要让 Isabella 想举办一次情人节派对，消息就能在 Agent 社会中自然扩散，其他人会决定是否参加、与谁同行，并最终形成集体活动。

这篇论文真正重要的地方：它第一次用一套相对完整的 Memory → Reflection → Planning → Action 架构，把"长期一致性"和"群体涌现行为"变成了可以工程化设计的问题。
SECTION 02

背景与动机：为什么单次 Prompt 无法构造长期人格？

论文面对的问题很明确：如果只在每次交互前给 LLM 一段 Persona Prompt，模型可以在某个时间点表现得像"一个人"，却很难处理不断增长的经历。今天与朋友发生的争执、昨天收到的邀请、下周要完成的计划，这些信息必须在未来某个具体时刻重新被找到、综合和利用。

规则系统的问题是覆盖不了开放世界。行为树、有限状态机可以精确控制"如果 A 就做 B"，但社交互动组合空间巨大，新出现的情境往往不在脚本里。强化学习虽然擅长学习策略，却需要稳定的奖励和可控环境，而开放式社会行为很难用单一奖励函数定义。

于是作者采取了一种更接近认知架构的思路：不要要求 LLM 把所有长期状态装进上下文，而是让 Agent 拥有一个不断增长的 Memory Stream；当需要做决定时，只检索当前最相关的记忆；更高层的规律则通过 Reflection 从多条记忆中逐步抽象出来；最后由 Planning 把目标、记忆与环境转成未来行动。

🗂️

记录"发生了什么"——可检索的经历库
💡

补充阐释：从今天的 Agent 工程角度，可以把它理解为把 Context Window 从"唯一状态容器"降级为工作内存，再用外部 Memory Store 承担长期状态。
SECTION 03

核心原理与技术架构

论文的核心并不是一个新模型，而是一种围绕 LLM 搭建的 Agent Cognitive Loop。它把一个 Agent 的行为拆为三个关键模块：Memory & Retrieval、Reflection、Planning；同时把环境感知、行动执行和 Agent 间对话接入这条闭环。

图 · Generative Agents 的工作闭环（感知—记忆—检索—反思—规划—行动）

3.1 · Memory Stream：不是把全部历史塞进 Prompt

Memory Stream 是 Agent 的长期经历库。每条记忆包含自然语言描述、创建时间和最近访问时间。真正关键的是 Retrieval：它综合相关性、近期性、重要性三个信号，为当前情况选出少量记忆。

论文实现中，recency 使用随 sandbox 时间衰减的指数函数，衰减因子为 0.995；importance 由 LLM 对事件"是否重大"打 1~10 分；relevance 则通过 embedding 计算记忆与当前 query 的余弦相似度。三者归一化后线性加权，最终取能放入上下文窗口的 Top memories。

Retrieval Score = Recency + Importance + Relevance 论文实现中三个权重均为 1

3.2 · Reflection：把"发生过什么"变成"我认识到什么"

只检索原始事件仍然不够。假设一个 Agent 在过去几天里反复观察到"我喜欢研究""我经常阅读论文""我总是在实验室待到很晚"，单独看每条记录都很普通，但组合起来可以形成更高层的认知——"我是一个非常投入研究的人"。

Reflection 就负责这个抽象过程。模型从一批近期、重要或相关的记忆出发，先形成局部结论，再将结论继续向上综合，形成 Reflection Tree。更高层的 Reflection 再写回 Memory Stream，于是它们可以影响之后的 Planning。

3.3 · Planning：先规划一天，再落到具体行动

Planning 让 Agent 不只是"看到什么就回答什么"。系统先根据 Agent 的身份、当前环境、已有记忆和 Reflection 生成较粗粒度的日程，然后递归细化到更具体的行动。行动进入环境后又会产生新的 Observation；如果环境发生变化，Agent 可以 React 并更新原有计划。

Plan自顶向下分解
→
Act执行具体行动
→
Observe接收环境反馈
→
Re-plan必要时更新计划
● 简化后的 Generative Agent 主循环（附原理注释）pseudocode
// ════════════════════════════════════════════════════════════
// 原理：Agent 的本质是"感知—认知—行动"的持续闭环，
// 重点不是调用哪个 API，而是"状态持续写回"：
//   观察产生记忆 → 记忆影响计划 → 行动改变环境 → 新观察进入下一轮
// 因此 Agent 拥有跨时间延续的状态，而不是每轮从零开始的问答。
// ════════════════════════════════════════════════════════════
while simulation_running:

    // ── ① 感知：观察环境（他 Agent 的行为、事件、对话等）──
    observation = observe(environment)

    // ── ② 记忆检索：以当前观察为线索，从记忆流中唤醒最相关的经历
    //    检索得分 = Recency(0.995^小时衰减) + Importance(LLM 1~10 分)
    //              + Relevance(embedding 余弦相似度)，三项等权 ──
    memories = retrieve(observation, memory_stream)

    // ── ③ 反思：当近期经历重要性积分累积到阈值（150）时触发，
    //    先生成高层问题，再检索证据，综合出抽象结论。
    //    Reflection 本身也写回记忆流 → 可层层递归成 Reflection Tree ──
    reflections = reflect(memories, memory_stream)

    // ── ④ 规划：综合 人设 + 具体记忆 + 抽象反思 + 当前观察，
    //    先生成粗粒度日程，再递归细化到具体行动 ──
    plan = plan(persona, memories, reflections, observation)

    // ── ⑤ 行动：执行计划的下一步，作用到共享环境 ──
    action = select_next_action(plan, observation)
    result = act(action, environment)

    // ── ⑥ 状态写回：新事件、计划和反思继续沉淀为长期记忆。
    //    注意：Plan 也被写入记忆 —— "我打算做什么"本身就是经历，
    //    行动改变了环境，下一轮的新观察可能触发 re-plan ──
    memory_stream.append(observation)
    memory_stream.append(result)
    memory_stream.append(plan)
SECTION 04

实验结果：真正被验证的是"长期一致性"和"群体涌现"

论文没有采用传统的单一任务 Accuracy，而是针对"可置信的人类行为"设计了两阶段评价。第一阶段对单个 Agent 做控制实验：100 名参与者比较不同架构产生的回答。第二阶段让 25 个 Agent 在 Smallville 连续运行两个完整游戏日，观察信息传播、关系形成和群体协调。

真正的实验结论：论文不是证明"LLM 可以模拟人类"，而是证明长期记忆、反思与规划的组合确实能让行为更连续、更可信，并进一步产生非脚本式的群体行为。

第一：Memory 不等于 Chat History

今天很多 Agent 仍把 Memory 理解为"历史消息 + 向量数据库"。这篇论文更早地指出，长期 Agent 需要的是可检索的经历、重要性判断和高层认知。原始事件解决"发生过什么"，Reflection 解决"这些事件意味着什么"。

第二：Planning 不是一次性生成 Todo List

论文强调计划需要递归细化，并且必须允许环境打断后重新规划。这个设计后来影响了大量 Agent Workflow：Plan 不应该是静态文档，而应该是可以被 Observation 和 Action 不断修正的状态。

第三：Multi-Agent 的价值来自交互，而不是数量

25 个 Agent 并不是简单并行回答问题，而是在共享环境中相互观察、交谈、记忆和行动。一个人的行动改变环境，进而改变另一个人的 Observation，再改变另一个人的 Planning；涌现行为正是在这种闭环里出现的。

我的理解：论文真正把"Agent"从一个会调用工具的 LLM，推进成了一个拥有持续状态 + 记忆 + 认知抽象 + 行为策略 + 环境反馈的长期运行实体。
SECTION 06

局限与工程陷阱：别把"像人"误解成"可靠"

论文的贡献非常大，但它同样坦诚地展示了问题。第一类错误来自 Memory Retrieval：如果没有找回关键经历，Agent 就可能做出不连贯的判断。第二类是 "memory embellishment"，即模型记得大方向，却在细节上额外添加不存在的事实。第三类是基础模型自身的语言风格，例如对话过度正式、过度礼貌和过度合作。

环境建模同样重要。论文发现，某些地点的社会规范如果没有明确写进世界状态，Agent 就可能做出违反常识的决定，例如商店已经关门却仍然进入，或在不合适的时段进入某个场所。

还有一个经常被忽略的问题：成本。论文指出，仅模拟 25 个 Agent 两天就消耗了数千美元 Token 费用，并耗费数天完成。因此这个架构适合复杂、长期、有高价值状态的任务，不适合简单问答。

更现实的生产化版本：短期上下文 + 事件 Memory + 结构化 Profile + Reflection Summary + 可编辑 Plan + 环境状态机，再配合 TTL、缓存、批量推理和异步调度。不要把论文原型直接复制进生产环境。
SECTION 07

开发者如何借鉴：把它迁移到今天的 Agent 系统

如果今天开发一个长期运行的个人助手、销售 Agent、虚拟角色或 Multi-Agent Research 系统，可以把论文架构转换成下面这一套工程组件：

论文概念现代工程实现核心问题
Memory StreamEvent Store / Document DB / Vector DB我过去经历了什么？
RetrievalHybrid Retrieval + Rerank + 时间衰减现在应该记住什么？
ReflectionSummary / Profile / Knowledge Graph过去这些经历说明什么？
PlanningTask Planner / State Machine / DAG下一步做什么？
ObservationEvent Bus / Tool Result / Environment State环境发生了什么？
ReactRe-plan / Interrupt / Recovery原计划失效后怎么办？
最值得借鉴的一点：Memory、Planner、Environment 三者要形成闭环。很多 Agent 项目只做"LLM + Tool Calling"，缺少持久化状态，因此任务一旦变长就开始失忆；另一些项目把所有内容都塞进向量库，却没有 Reflection，于是记得很多，却不知道哪些事实应该上升成长期知识。
SECTION 08

总结与展望：今天的 Memory Agent，仍然站在这篇论文的肩膀上

Generative Agents 最重要的贡献，并不是构造了一个漂亮的 Smallville，而是证明了一种新的 Agent 架构范式：LLM 负责开放式认知，外部系统负责长期状态管理。当 Observation 被记录、Memory 被检索、Reflection 被抽象、Plan 被执行，Agent 才真正具备跨时间保持一致性的可能；当多个 Agent 共享环境并互相影响时，关系、信息传播和集体协调就可能自然出现。

从今天回看，这条路线已经延伸出大量 Memory Agent、AI NPC、数字人、社会模拟与长期个人助手的研究。未来更值得关注的不是"给 Agent 加更多记忆"，而是记忆应该如何形成、如何遗忘、如何纠错，以及 Reflection 如何避免把错误经验固化成长期信念。

换句话说，真正成熟的 Agent 不应该只是"能回答问题"，而应该能够解释：我为什么记得这件事、它从哪里来、它改变了我的什么判断、我下一步为什么要这么做。
