# 用 200 步 LoRA 给 DeepSeek-R1-Distill-Llama-8B 灌点中文医学知识，到底改变了什么

最近在 Kaggle 上跑了一个不大的微调实验：拿 `unsloth/DeepSeek-R1-Distill-Llama-8B` 做底座，配合 Unsloth + LoRA，在一份中文医学推理数据集上训练 200 步，然后让微调前后的模型分别回答同三道临床题，对照看效果。

这篇文章不是一份"评测报告"，更像是我跑完之后翻着输出日志自己捋一遍：哪些地方符合预期，哪些地方让我愣了一下，loss 曲线说明了什么、又遮蔽了什么。

## 为什么选这个组合

R1-Distill 系列模型的特点是自带 `<think>...</think>` 的思维链格式，这正好和医学问答这种需要"先推理、再下结论"的任务契合。Unsloth 的卖点是用更少显存、更快的速度做同样的微调，对我这种只有一张 T4（14.5GB 显存）的环境来说基本是刚需——4bit 量化加载 + LoRA，是唯一能把 8B 模型塞进 T4 还留出训练空间的路子。

数据集用的是 `FreedomIntelligence/Medical-R1-Distill-Data-Chinese`，这份数据本身就是用 R1 类模型蒸馏生成的，每条样本包含 `question`、`reasoning (reasoning_content)`、`response (content)` 三个字段——也就是题目、推理过程、最终答案是分开存的。这意味着训练数据本身的思维链质量，直接决定了微调后模型"装"出来的推理风格像谁。这点我后面会再提一句，因为它跟我观察到的某个现象有关。

完整数据集有 17000 条，这次只取了前 1600 条（`split="train[:1600]"`）。倒不是显存撑不住，单纯是先用一个小切片验证 pipeline 跑得通、效果方向对不对，没打算一次性梭哈全量数据。

## Prompt 模板：训练和推理要对齐

这里有个容易踩坑但又很基础的细节：训练时用的 prompt 模板，必须和推理时用的模板保持一致，否则模型学到的格式跟你测试时构造的输入根本不是一套东西，效果会莫名其妙地差。

我用的模板是经典的 Alpaca 风格变体：

```
Below is an instruction that describes a task, paired with an input that provides further context.
Write a response that appropriately completes the request.
Before answering, think carefully about the question and create a step-by-step chain of thoughts to ensure a logical and accurate response.

### Instruction:
You are a medical expert with advanced knowledge in clinical reasoning, diagnostics, and treatment planning.
Please answer the following medical question.

### Question:
{}

### Response:
<think>
{}
</think>
{}
```

训练时把 `question`、`reasoning`、`response` 三个字段分别填进三个占位符，再在结尾手动拼上 `EOS_TOKEN`——这一步千万不能漏，不加 EOS 的话模型会不知道什么时候该停，生成时容易没完没了地往下编。推理时则是只填第一个占位符（问题），把 `<think>` 标签留空等模型自己续写，这样才能看到它的"原生思考过程"有没有被微调改变。

## LoRA 配置：0.52% 的参数量

```python
model = FastLanguageModel.get_peft_model(
    model,
    r = 16,
    target_modules = ["q_proj", "k_proj", "v_proj", "o_proj",
                      "gate_proj", "up_proj", "down_proj"],
    lora_alpha = 16,
    lora_dropout = 0,
    bias = "none",
    use_gradient_checkpointing = "unsloth",
    random_state = 3407,
    use_rslora = False,
    loftq_config = None,
)
```

把 attention 的四个投影（q/k/v/o）和 MLP 的三个投影（gate/up/down）全部挂上 LoRA，rank 给到 16，alpha 也是 16（等于 rank，相当于缩放系数为 1，是比较中性、没有刻意放大或缩小更新幅度的选择）。日志里报出来的可训练参数是 **41,943,040**，占总参数 8,072,204,288 的 **0.52%**——这个数字本身没什么好惊讶的，LoRA 的设计目标就是让你只调一小撮参数，但每次看到这种百分之零点几就能让模型"学到东西"的对比，还是会觉得有点不真实。

训练超参数这边走的是标准配置：

```python
SFTConfig(
    per_device_train_batch_size = 2,
    gradient_accumulation_steps = 4,
    warmup_steps = 5,
    max_steps = 200,
    learning_rate = 1e-4,
    logging_steps = 1,
    optim = "adamw_8bit",
    weight_decay = 0.001,
    lr_scheduler_type = "linear",
    seed = 3407,
)
```

有效 batch size 是 `2 × 4 × 1 = 8`，200 步意味着模型实际"看过"了 1600 条样本（刚好覆盖整个切片一次，等于 1 个 epoch）。学习率 1e-4 配合 8bit AdamW，这是 Unsloth 官方示例里常见的搭配，没有特别调过——这次实验的目的是验证流程和方向，不是榨干超参数空间。

## Loss 曲线：从 1.44 降到 1.02，但中间不是一条平滑的下坡路

200 步的训练日志里，每一步的 loss 我都记了下来。前 10 步的均值是 **1.437**，最后 10 步的均值是 **1.018**，整体降了大约 29%。最低点出现在第 149 步，loss 是 **0.834**。

但如果只看"首尾均值降了多少"，会错过一个更有意思的细节：loss 曲线不是单调下降的，波动相当明显。比如第 191-200 步这最后十步里，数值是这样跳的：

```
0.9312, 0.9819, 0.9379, 0.9270, 1.0722, 1.0701, 1.0061, 1.1001, 1.0997, 1.0564
```

最低点在 194 步（0.927），但训练就在第 200 步结束，此时 loss 反而回弹到了 1.056——也就是说如果早停在第 194 步，账面数字会更好看一点。这种摆动在小数据量、短步数的微调里很常见，单条 batch 的样本难度差异（比如这次的题目难度跨度从急性阑尾炎到胰腺炎并发症的多重并发症推理）会让逐步 loss 看起来像噪声。200 步、单 epoch 这个量级，还远没到能看出稳定收敛曲线的程度，更准确的说法是"训练正在往正确方向走，但还没走到平台期"。

另外值得记一下的是耗时：200 步在单张 T4 上跑了 **2 小时 16 分钟**。平均每步 40 多秒，这个速度对于做多轮超参数搜索来说是有点吃力的——如果要认真调学习率或者 rank，这个迭代周期会成为瓶颈，后面再做类似实验大概会考虑上更高一档的卡，或者先在更小的数据切片上做快速验证。

## 三道题，微调前后到底差在哪

测试集是手写的三道难度递增的临床推理题：

- **简单题**：24 岁女性，右下腹转移性腹痛 + McBurney 点压痛反跳痛 → 经典急性阑尾炎的教科书描述
- **中等题**：65 岁男性，左下腹痛 + 发热 + 便秘 + 结肠憩室病史 → 指向乙状结肠憩室炎，同时考查"为什么急性期不能做钡剂灌肠/肠镜"这种操作层面的临床判断
- **难题**：52 岁重症胰腺炎患者并发呼吸困难、低氧血症、胸片双肺斑片影 → 考的是胰腺炎并发 ARDS 的识别和处理原则，涉及三个连续追问

先放一张速览表，对应关系一目了然，下面再逐题展开细节：

| 难度 | 微调前判断 | 微调后判断 | 教科书方向参考 | 一句话评价 |
| :--- | :--- | :--- | :--- | :--- |
| 简单（阑尾炎） | 急性肝炎（解剖定位错误） | 脾结核/脾炎（定位拉回右下腹，但诊断仍非标准答案） | 急性阑尾炎 | 起点修正了，终点还没对 |
| 中等（憩室炎） | 急性炎症性梗阻/炎症性痢疾（与病史关联松散） | 腹膜下游离脓肿（开始挂钩病史，但机制叙述有跳跃） | 乙状结肠憩室炎伴脓肿可能 | 结构变像了，逻辑还在拼接 |
| 困难（ARDS） | 腹膜肺致单侧通气不足（输出被截断，机制生造） | ARDS（与腹膜炎性休克机制混讲，止血治疗建议不严谨） | SIRS 致弥漫性肺泡损伤 | 格式像报告，核心机制仍未命中 |

### 简单题：微调前直接答错了大方向

这是最让我意外的一个对比。微调**前**的模型，看完麦氏点压痛反跳痛的描述，推理路径绕到了"肝脏问题"——它把麦氏点(McBurney's point)和脾脏/肝脏的解剖位置搞混了，一路论证下来给出的结论是**急性肝炎**，影像学建议也是腹部超声评估肝脏。这个错误挺基础的，说明底座模型在没有针对性数据强化的情况下，对这种经典体征-解剖定位的关联记忆并不牢靠，尽管它的"思考过程"写得头头是道、逻辑自洽——这才是最容易让人放松警惕的地方：推理链读起来很有说服力，但起点就错了。

微调**后**，模型把麦氏点正确关联到了右下腹/阑尾区域，给出的诊断方向变成了脾结核或脾炎，并建议腹部超声。诊断本身依然不是标准答案（教科书答案应该是急性阑尾炎，首选检查可以是腹部超声或CT），但至少推理的解剖学起点修正了，不再是离题千里的"肝脏"。换句话说，这次微调没有让模型变成"对"，但确实把它从一个更离谱的错误方向，往中等离谱的方向拉了一截。

### 中等题：诊断方向开始"挂钩"病史，但术语用得不太干净

微调前，模型给出的最可能诊断是"急性炎症性梗阻（特别是炎症性痢疾）"，这个诊断和患者的结肠憩室病史关联得比较松散，更像是泛化地套用了"腹痛+发热+白细胞升高=感染性肠道疾病"的模板。

微调后，模型给出的诊断变成了"腹膜下游离脓肿"，并主动关联到了结肠憩室病史，鉴别诊断也提到了"结核性腹膜炎"和"细菌性肠炎"。这个回答有一个问题：它在解释机制时，把肠结核、脾结核、腹膜炎几个概念混着用，逻辑链条里有些跳跃（比如直接从"结肠憩室病史"跳到"肠道内结核"，中间缺一步)。可以看出，模型确实开始往数据集训练过的"鉴别诊断+机制解释"的回答结构上靠了，结构感更强，但具体的医学事实链条还有明显的拼接痕迹。

不过有一点是稳定改善的：关于"为什么急性期要避免钡剂灌肠和纤维结肠镜"，微调后的回答给出的理由（刺激病变区域、可能导致穿孔或感染扩散）比微调前（"钡盐肠道梗阻"这个说法本身就比较牵强）更接近临床上真实的顾虑。

### 难题：结构变规整了，但核心机制判断仍然不准

这道题需要回答三个子问题：并发了什么病、怎么纠正低氧血症、怎么动态平衡补液。

需要先说明一点：微调前这道题的生成在我导出的日志里被截断了，没有跑出完整答案。但截断前的部分已经能看出问题所在：模型把患者的呼吸困难和低氧血症归因为"腹膜肺"导致的"一侧肺通气不足"——这个解释路径本身在医学上就比较生造，听起来像是把"腹膜炎"和"肺"两个概念强行嫁接出来的新词。即便后续内容没跑完，这个开头给出的核心机制判断已经偏了，所以拿这段去和微调后的完整回答做对比，依然是有效的。

微调后的回答在结构上有明显进步：清楚地分成了三段回答三个子问题，并且给出了具体的治疗手段列表（机械通气、抗生素、止血治疗、血管内液体治疗、补液动态监测原则），格式上更像一份"正经的临床分析"。但核心的病理生理机制判断，依然把"急性呼吸窘迫综合征(ARDS)"和"腹膜炎性休克导致肺灌注不足"这两个机制混着讲，没有抓住胰腺炎并发 ARDS 最关键的机制——全身炎症反应综合征(SIRS)引发的弥漫性肺泡毛细血管损伤。另外，列出的"止血治疗（血小板、PAHs等）"这一项也站得不太稳——胰腺炎并发 ARDS 的标准处理思路里，抗凝/止血并不是常规推荐手段，这条建议读起来更像是从训练数据里某些不完全对症的治疗描述里"嫁接"过来的。这种具体到某个治疗手段层面的偏差，靠单纯的 SFT 大概很难筛掉，因为 SFT 本质上是在模仿训练数据的输出分布，如果数据里混了不够严谨的治疗建议，模仿出来的内容自然会带着同样的瑕疵——这道题本身对一个 8B 模型、用 1600 条数据训 200 步来说，确实偏难，没指望它能完全答对，但这个对比能看出"答案变得更像医学报告"和"医学判断真的变准确"是两件可以脱钩的事。

## 为什么 1600 条、200 步纠正不了这些错误

把三道题的问题摆出来之后，更应该问一句：这些错误本质上是什么类型的错误，为什么这次训练量级解决不了。我把能想到的原因排了一下，大致分四类，权重不一定准，但方向应该是对的。

**第一，1600 条是覆盖不了"麦氏点定位"这种具体知识点的。** 这份数据集是综合性的中文医学问答蒸馏数据，17000 条样本横跨各个科室、各种病种，1600 条只是按顺序切的前 1/10 ——没有做任何采样上的针对性筛选，更不会保证里面包含足够多"急性阑尾炎"或者"麦氏点"相关的样本。换句话说，模型微调后能不能答对这道题，很大程度上取决于这 1600 条里"恰好"有没有覆盖到这类知识，而不是微调本身有什么神奇的纠错能力。LoRA 调整的是模型的"输出分布偏好"，不是知识库——如果某个具体知识点在训练集里根本没出现过，单靠 SFT 是没法把它"教"进去的，顶多是激发模型本来就有、但平时不太会用的那部分预训练知识。这也是为什么"针对性补充错误样本"会比"盲目堆量"更有效的根本原因：不是数据量不够，而是数据和错误点没对上。

**第二，0.52% 的参数量级、配合只有 1 个 epoch，决定了这次训练更接近"风格对齐"而不是"知识注入"。** LoRA 本身的设计目标就是用很小的参数增量去逼近一个新的输出分布，这个分布最容易学的、信号最强的部分，是数据里那些高频出现、模式统一的表层特征——比如"先打 `<think>` 标签、再分点列鉴别诊断、再加粗结论"这种结构性的东西，因为这些模式几乎在每一条训练样本里都会重复出现，梯度信号密集、一致，模型很快就能抓住。而具体到某个疾病的解剖定位、某个病理机制的因果链条，这些知识在 1600 条样本里大概率是稀疏、零散分布的——一个机制可能只在三五条样本里出现过，信号弱，1 个 epoch 根本不够把它从噪声里"捞"出来固化成稳定输出。这跟前面 loss 曲线降了 29% 但案例对比里事实错误依然存在，其实是同一件事的两个侧面：loss 下降反映的正是那个"信号密集"的表层模式被学到了，而稀疏的事实性知识进步缓慢，二者权重悬殊，平均到 loss 里就被表层模式的快速下降"盖住"了。

**第三，三道测试题本身的难度，可能超出了这次训练能纠正的范围。** 阑尾炎的麦氏点定位是相对基础的解剖学常识错误，理论上数据集里只要有几条相关样本反复出现，是有机会被纠正的；但胰腺炎并发 ARDS 涉及的"肠-淋巴-肺轴""SIRS 引发弥漫性肺泡损伤"这类机制，本身就是相对专业、细分的临床知识，需要的不仅是"见过这个病"，还需要"见过这个病的这个并发症、并且推理链条写得足够清楚"——这种样本在综合性数据集里的密度可能更低，超纲的概率也更高。换句话说，三道题虽然是按"难度递增"设计的，但这个难度梯度，也大概率对应着训练数据里相关知识的稀疏程度梯度，两者大概是同向变化的，这可能是巧合，也可能是医学知识本身的复杂度和数据覆盖度天然相关——但这只是基于这一份观察做的推测，没有用其他测试集验证过。

留一个我自己没能验证的开放问题：这份数据集到底是怎么排序的——如果是按疾病系统分类堆放（比如循环系统、呼吸系统、消化系统依次排列），那"前 1600 条"可能根本不包含任何阑尾炎/麦氏点相关样本，模型答错就更接近"零样本泛化失败"而不是"学得不够"；但如果是随机打散的，结论又会不一样。理想情况下应该实际统计一下这 1600 条里 `question` 字段命中"阑尾/麦氏点/右下腹"这类关键词的频次——但写这篇文章时我没能拿到这份数据集（环境的网络访问限制了 huggingface.co），所以这一点目前只能是猜测，没法给出实测数字，留给愿意复现的人去验证。

**第四，没有做数据集本身的质量检查，意味着"天花板"可能本来就不高。** 前面提过，这份数据的 `reasoning_content` 字段是另一个模型蒸馏生成的，如果原始推理链里本来就存在事实错误或逻辑跳跃，微调相当于在拿一个不完全可靠的"老师"去教一个学生——老师自己说不清楚的地方，学生也学不会说清楚。这次训练完全没有对训练数据做抽样质检，所以现在没法判断"模型学得不够"和"数据本身就有上限"这两个原因各占多少比重。这也是为什么"接下来想做的事"里我把"拆解训练数据本身的推理质量"列为一个独立方向，而不是和"扩大数据量"合并——如果不先看一眼老师讲得对不对，单纯加大数据量可能只是在更大规模上复制同样的问题。

这四点放在一起看，其实指向同一个结论：1600 条、200 步、1 个 epoch 这个量级，本质上只够让模型完成一次"风格迁移"，知识层面的纠错能不能发生，更像是撞运气——撞上了训练集里恰好覆盖到的知识点，撞不上的，不管 loss 降到多少，案例对比里大概率还是错的。

还有第五点，性质不太一样，值得单独拎出来：训练和推理时模型"看到"的 `<think>` 内容，根本不是一回事。训练时填进 `<think>{}</think>` 这两个占位符的，是数据集里现成的、已经写好的高质量推理过程——这相当于一种 teacher forcing，模型每一步都在"已知后面会怎么推下去"的前提下学习怎么续写。但推理时是把 `<think>` 标签留空，让模型从零开始自回归生成，每一步只能基于自己刚生成的内容继续往下走，没有任何"标准答案"可以参照。这意味着如果模型在推理的第一两句就把解剖定位搞错了（比如把麦氏点扯到肝脏/脾脏），后面的整条推理链都是在一个错误的起点上自我强化、自圆其说——而训练数据从来没有教过它"发现自己推错了之后该怎么纠偏"，因为训练时它看到的从来都是一条已经正确的链路。这可能也是为什么"思考过程读起来逻辑自洽，但起点就错了"这种现象会反复出现：错误一旦在推理早期出现，模型没有机制去识别和回退，只会顺着错误的方向把故事讲完。这个机制目前也只是基于这次训练范式（纯 SFT、teacher forcing）的合理推断，没有在这次实验里专门设计对照去验证，但如果以后想解决这类"早期推理偏移"的问题，路径上更对症的大概是拒绝采样微调或者偏好优化（如 DPO）之类、能在生成结果层面做纠偏的方法，而不是单纯堆 SFT 数据。

## 一个值得多想一层的现象：风格学得比事实快

把三道题的微调前后输出放在一起看，一个比较明显的规律是：**回答的格式和结构变化，比医学事实的准确性变化更快、更明显**。微调后的输出普遍带上了 Markdown 标题、加粗关键词、分点列举鉴别诊断和处理建议——这显然是训练数据（来自 R1 类模型蒸馏）里"回答风格"的直接迁移。但具体到某个解剖定位对不对、某个病理机制讲得通不通，进步幅度明显要慢得多，甚至有退步（比如中等题里把肠结核和腹膜炎的关系讲得更绕了）。

这其实是一个挺重要的提醒：**如果只用"回答看起来是否专业"来肉眼评估微调效果，很容易高估模型的真实进步**。1600 条数据、200 步、单 epoch，这个量级足够让模型学会"像 R1 一样写思维链、像医学报告一样组织答案"，但不足以系统纠正它在具体医学知识上的薄弱点——这两者需要的数据量级和训练时长可能完全不是一个尺度。

回头看 loss 曲线，从 1.44 降到 1.02，下降是真实的，但 loss 衡量的是"预测下一个 token 的能力"，而 token 预测能力提升，很大一部分会体现在"句式、术语密度、回答结构"这种表层模式上，并不直接等价于"诊断更准了"。这次实验某种程度上是把这个理论上的认知，变成了一个可以拿三道题对照着看的具体案例。

## 接下来想做的几件事

这次实验更像是一次 pipeline 验证：确认 Unsloth + LoRA 在单卡 T4 上能跑通、确认训练和推理的 prompt 模板对齐、确认 loss 在合理下降。下一步如果要往"真正让模型在医学推理上变准"这个目标走，几个方向是比较明确的：

1. **扩大数据量、增加 epoch**：1600 条/200 步只是全量数据的不到 10%，且只训了一轮。把训练量提上去，再看 loss 曲线是不是真的能进入平台期，以及医学事实准确率有没有对应提升。

2. **引入定量评测，而不是只看三道题的肉眼对比**：比如用同一份医学选择题/简答题构建一个小型 held-out 测试集，跑微调前后的准确率对比，或者用 GPT-4/Claude 之类的模型做裁判打分，这样能避免"看起来更专业"和"答得更对"被混为一谈。

3. **针对性补充错误样本**：这次暴露出来的麦氏点定位错误、腹膜炎/肠结核机制混淆，都是相对具体、可定位的知识缺口。如果能针对这类典型错误补充对应的训练样本（哪怕是几十条高质量的纠正性样本），可能比单纯堆量更有效率。

4. **拆解训练数据本身的推理质量**：因为这份蒸馏数据集的 `reasoning_content` 本身是另一个模型生成的，如果原始推理链里就存在事实错误或逻辑跳跃，微调只是在"复制"这些缺陷而非创造新的。下次可能会先抽样人工检查一批 reasoning 内容的质量，再决定是否要清洗或重新生成。

5. **对比不同 LoRA rank/学习率组合**：这次只跑了一组配置，2 小时 16 分钟一轮的成本意味着多组对比需要更高效的迭代方式——可能会先在更小的步数（比如 50 步）上做快速 sanity check，再决定哪个配置值得跑满。

6. **统计训练切片的实际知识覆盖度**：把这 1600 条样本的 `question` 字段拉出来做一次关键词统计，看看到底有没有覆盖到这次测试题对应的知识点（阑尾炎、憩室炎、ARDS 相关）。这次受限于网络环境没能跑这一步，是这篇文章里比较明显的一个验证缺口，下次会优先补上。

7. **尝试拒绝采样微调或 DPO 之类能在生成结果层面纠偏的方法**：如果"早期推理偏移、没有纠错机制"确实是部分错误的来源，那纯 SFT 大概不是对症的工具，值得对比一下引入偏好优化之后，这类错误是否会减少。

这次实验本身谈不上"成功"或"失败"，更准确的说法是：验证了一条能跑起来的最小路径，同时也用三个具体例子提醒自己——表面变专业，和底层变准确，是两件需要分别验证的事。
