1. 引言：为什么需要融合检索？

在之前的篇章中，我们构建的 RAG 系统几乎都依赖单一的向量检索——将查询和文档编码为高维向量，通过余弦相似度找到语义最相近的文本块。这种方法在"理解意图"方面表现出色，但它有一个根本性的盲区：

向量检索的盲区

当用户查询包含精确的专业术语、产品名称或特定关键词时，向量检索可能因为语义空间的"模糊匹配"特性，将包含精确术语的文档排在语义相近但术语不精确的文档之后。换句话说，向量检索擅长"理解意思"，但不擅长"精确找词"。

反过来，传统的关键词检索（如 BM25）恰好擅长精确匹配，却无法理解同义词和语义关系。

向量检索的优势

  • 理解语义相似性
  • 处理同义词和改写
  • 捕捉上下文含义
  • 对措辞变化鲁棒

BM25 关键词检索的优势

  • 精确匹配专业术语
  • 基于词频的统计信号
  • 无需嵌入模型，成本低
  • 对稀有关键词敏感

融合检索（Fusion Retrieval）的核心动机正是：为什么不把两者的优势结合起来？

2. 核心思想：语义 + 关键词的双路互补

融合检索的核心思想可以用一句话概括："先分头行动，再综合决策"。系统同时运行两条检索路径——语义向量搜索和 BM25 关键词搜索——然后通过归一化和加权融合，将两种不同量纲的分数统一到同一个尺度上，最终按综合分数排序返回结果。

关键设计决策

与第 8 篇的重排序不同，融合检索不是在初始检索之后"二次过滤"，而是在检索阶段本身就将两种信号融合。这意味着每种文档都会同时获得语义分数和关键词分数，最终的排序是两种信号的综合体现。

4. 核心公式：归一化 + 加权融合

融合检索的核心在于如何将两种不同量纲的分数合并。向量搜索返回的余弦相似度范围是 [-1, 1]（实际通常 [0, 1]），而 BM25 分数的范围取决于文档长度和词频分布，可能从 0 到几十不等。直接相加毫无意义——必须先归一化。

融合公式

combined_score = alpha * norm_vector_score + (1 - alpha) * norm_bm25_score

Min-Max 归一化

归一化将两种分数都映射到 [0, 1] 区间：

norm_score = (score - min) / (max - min + epsilon)

其中 epsilon = 1e-8，防止分母为零

归一化后，两种分数都在 [0, 1] 尺度上，此时加权融合才有意义：

  • alpha = 0.5：语义和关键词同等重要（默认值）
  • alpha = 0.8：更侧重语义理解
  • alpha = 0.2：更侧重关键词匹配
# 归一化分数 —— 融合检索的核心步骤
epsilon = 1e-8  # 防止除以零

# Min-Max 归一化向量分数
norm_vector_scores = (vector_scores - np.min(vector_scores)) / \
                     (np.max(vector_scores) - np.min(vector_scores) + epsilon)

# Min-Max 归一化 BM25 分数
norm_bm25_scores = (bm25_scores - np.min(bm25_scores)) / \
                   (np.max(bm25_scores) - np.min(bm25_scores) + epsilon)

# 加权融合
combined_scores = alpha * norm_vector_scores + \
                  (1 - alpha) * norm_bm25_scores
为什么选择 Min-Max 归一化？

Min-Max 归一化保留了原始分数的相对排序，同时将值域压缩到 [0, 1]。相比 Z-score 标准化，它更直观——归一化后的 0 分表示"在该方法中排名最低"，1 分表示"在该方法中排名最高"。加权融合后的分数也可以直接解读为"综合排名质量"。

5. 代码解读：BM25 索引与搜索

BM25（Best Matching 25）是信息检索领域最经典的排序算法之一。它基于词频（TF）和逆文档频率（IDF）来评估文档与查询的相关性。我们使用 rank_bm25 库来实现。

from rank_bm25 import BM25Okapi

def create_bm25_index(chunks):
    """
    根据给定的文本块创建 BM25 索引。

    参数:
        chunks (List[Dict]): 文本块的列表

    返回:
        BM25Okapi: 一个 BM25 索引
    """
    # 从每个块中提取文本
    texts = [chunk["text"] for chunk in chunks]

    # 将每个文档按空格拆分为标记（token）
    tokenized_docs = [text.split() for text in texts]

    # 使用标记化的文档创建 BM25 索引
    bm25 = BM25Okapi(tokenized_docs)

    print(f"Created BM25 index with {len(texts)} documents")
    return bm25

BM25 搜索函数为每个文档计算与查询的 BM25 分数，并按分数降序排列：

def bm25_search(bm25, chunks, query, k=5):
    """
    使用查询搜索 BM25 索引。

    参数:
        bm25 (BM25Okapi): BM25 索引
        chunks (List[Dict]): 文本块列表
        query (str): 查询字符串
        k (int): 返回的结果数量

    返回:
        List[Dict]: 带有分数的前 k 个结果
    """
    # 将查询按空格分割为词元
    query_tokens = query.split()

    # 获取查询词对已索引文档的 BM25 得分
    scores = bm25.get_scores(query_tokens)

    results = []
    for i, score in enumerate(scores):
        metadata = chunks[i].get("metadata", {}).copy()
        metadata["index"] = i
        results.append({
            "text": chunks[i]["text"],
            "metadata": metadata,
            "bm25_score": float(score)
        })

    # 按 BM25 得分降序排序
    results.sort(key=lambda x: x["bm25_score"], reverse=True)
    return results[:k]
BM25 vs 向量搜索的本质区别

BM25 是"词面匹配"——查询中有 transformer，文档中也必须有 transformer 才能得分。向量搜索是"语义匹配"——即使文档中没有 transformer，但提到了 attention mechanism 或 BERT，也可能因为语义相近而获得高分。两者互补，正是融合检索的理论基础。

6. 代码解读：融合检索核心函数

这是整个融合检索系统最关键的部分。函数同时执行向量搜索和 BM25 搜索，然后对结果进行归一化和加权融合：

def fusion_retrieval(query, chunks, vector_store, bm25_index,
                     k=5, alpha=0.5):
    """
    融合检索：结合向量搜索和 BM25 搜索。

    参数:
        query (str): 查询字符串
        chunks (List[Dict]): 原始文本块
        vector_store (SimpleVectorStore): 向量存储对象
        bm25_index (BM25Okapi): BM25 索引对象
        k (int): 返回结果的数量
        alpha (float): 向量分数的权重 (0-1)

    返回:
        List[Dict]: 基于组合分数的前 k 个结果
    """
    epsilon = 1e-8

    # === Step 1: 双路检索 ===

    # 向量搜索：获取所有文档的余弦相似度
    query_embedding = create_embeddings(query)
    vector_results = vector_store.similarity_search_with_scores(
        query_embedding, k=len(chunks)
    )

    # BM25 搜索：获取所有文档的 BM25 分数
    bm25_results = bm25_search(
        bm25_index, chunks, query, k=len(chunks)
    )

    # === Step 2: 构建分数映射 ===

    # 将文档索引映射到各自的分数
    vector_scores_dict = {
        r["metadata"]["index"]: r["similarity"] for r in vector_results
    }
    bm25_scores_dict = {
        r["metadata"]["index"]: r["bm25_score"] for r in bm25_results
    }

    # 确保所有文档在两种方法中都有分数
    all_docs = vector_store.get_all_documents()
    combined_results = []
    for i, doc in enumerate(all_docs):
        combined_results.append({
            "text": doc["text"],
            "metadata": doc["metadata"],
            "vector_score": vector_scores_dict.get(i, 0.0),
            "bm25_score": bm25_scores_dict.get(i, 0.0),
            "index": i
        })

    # === Step 3: Min-Max 归一化 ===

    vector_scores = np.array([d["vector_score"] for d in combined_results])
    bm25_scores = np.array([d["bm25_score"] for d in combined_results])

    norm_vector_scores = (vector_scores - np.min(vector_scores)) / \
        (np.max(vector_scores) - np.min(vector_scores) + epsilon)
    norm_bm25_scores = (bm25_scores - np.min(bm25_scores)) / \
        (np.max(bm25_scores) - np.min(bm25_scores) + epsilon)

    # === Step 4: 加权融合 ===

    combined_scores = alpha * norm_vector_scores + \
                      (1 - alpha) * norm_bm25_scores

    # 将融合分数写回结果
    for i, score in enumerate(combined_scores):
        combined_results[i]["combined_score"] = float(score)

    # === Step 5: 排序返回 Top-K ===

    combined_results.sort(
        key=lambda x: x["combined_score"], reverse=True
    )
    return combined_results[:k]
全量检索的设计意图

注意：向量搜索和 BM25 搜索都使用了 k=len(chunks)，即全量检索所有 42 个文档的分数，而非仅取 Top-5。这是因为归一化需要知道所有分数的最大值和最小值——如果只检索部分文档，归一化的基准就不完整，融合结果会失真。

7. 代码解读：完整融合 RAG 管道

将融合检索集成到 RAG 管道中非常简洁。同时，我们还实现了 vector_only_rag 和 bm25_only_rag 作为对比基线：

def answer_with_fusion_rag(query, chunks, vector_store,
                           bm25_index, k=5, alpha=0.5):
    """使用融合 RAG 方法回答查询。"""
    # 1. 融合检索
    retrieved_docs = fusion_retrieval(
        query, chunks, vector_store, bm25_index, k=k, alpha=alpha
    )

    # 2. 格式化上下文（用分隔符区分不同文本块）
    context = "\n\n---\n\n".join(
        [doc["text"] for doc in retrieved_docs]
    )

    # 3. LLM 生成回答
    response = generate_response(query, context)

    return {
        "query": query,
        "retrieved_documents": retrieved_docs,
        "response": response
    }


def vector_only_rag(query, vector_store, k=5):
    """仅使用向量检索的 RAG（对比基线）。"""
    query_embedding = create_embeddings(query)
    retrieved_docs = vector_store.similarity_search_with_scores(
        query_embedding, k=k
    )
    context = "\n\n---\n\n".join(
        [doc["text"] for doc in retrieved_docs]
    )
    response = generate_response(query, context)
    return {"query": query, "retrieved_documents": retrieved_docs,
            "response": response}


def bm25_only_rag(query, chunks, bm25_index, k=5):
    """仅使用 BM25 检索的 RAG（对比基线）。"""
    retrieved_docs = bm25_search(bm25_index, chunks, query, k=k)
    context = "\n\n---\n\n".join(
        [doc["text"] for doc in retrieved_docs]
    )
    response = generate_response(query, context)
    return {"query": query, "retrieved_documents": retrieved_docs,
            "response": response}

8. alpha 参数：调节语义与关键词的平衡

alpha 参数控制着融合检索中语义信号与关键词信号的相对权重。不同的 alpha 值适用于不同类型的查询和文档集合：

alpha 值向量权重BM25 权重适用场景
0.00%100%纯关键词检索（如精确产品型号查询）
0.220%80%关键词主导，辅以语义理解
0.550%50%均衡融合（默认值，适合大多数场景）
0.880%20%语义主导，辅以关键词精确匹配
1.0100%0%纯语义检索（等同于向量检索）
如何选择最佳 alpha？

最佳 alpha 值取决于查询类型和文档特性。经验法则：

  • 文档中包含大量专业术语 → 降低 alpha（更依赖 BM25）
  • 查询措辞多变、同义词丰富 → 提高 alpha（更依赖向量）
  • 不确定时 → 从 alpha=0.5 开始，通过评估调优

清晰度与连贯性 清晰 清晰但无用 清晰且信息密度高
关键发现

融合检索在这个查询上表现最好。它不仅提供了最相关、最正确、最全面的回答，还提到了 BERT 和 GPT 等具体模型名称——这些细节在单独的向量检索和 BM25 检索中都没有出现。这证明了融合检索能够从两种检索路径中互补信息，为 LLM 提供更丰富的上下文。

各方法适用场景总结

向量检索擅长

  • 语义理解类查询
  • 同义词和改写处理
  • 上下文含义捕捉
  • 模糊意图查询

BM25 擅长

  • 精确术语匹配
  • 稀有关键词检测
  • 低成本快速检索
  • 可解释性强的场景
融合检索的最佳使用场景

融合检索在以下场景中优势最大：

  • 混合查询：查询同时包含语义概念和精确术语
  • 多主题文档：文档涵盖多个相关但不同的主题
  • 高召回需求：需要尽可能多地检索相关信息
  • 不确定哪种方法更好：融合提供了"保险"策略

11. 总结与展望

本篇核心收获

  1. 双路互补：向量检索擅长语义理解，BM25 擅长精确匹配——融合检索将两者结合，取长补短。
  2. 归一化是关键：不同检索方法的分数具有不同量纲，必须通过 Min-Max 归一化统一到 [0, 1] 尺度后才能进行有意义的加权融合。
  3. alpha 参数：控制语义与关键词的平衡点，默认 0.5 在大多数场景下是一个合理的起点。
  4. 实验验证：在 transformer 应用查询上，融合检索的回答质量显著优于单独的向量检索或 BM25 检索。

融合检索的核心价值

不追求任何单一方法的极致，而是通过信号互补实现更稳健的检索质量。
