🎯 1. 为什么需要语义分块？

在上一篇文章中，我们实现了基础 RAG：将文档按固定字符数或 token 数进行切块，然后基于向量相似度检索最相关的片段。这种"固定长度分块"简单高效，但存在一个根本问题——

💥 痛点：语义断裂

固定长度分块不关心内容边界，可能在一段完整论述的正中间切下一刀。结果：前半块和后半块各自丢失上下文，检索时要么匹配不到正确片段，要么把不相关的内容混入上下文窗口。

举个例子：假设一段文本在讲"机器学习的应用"，紧接着下一段在讲"自然语言处理的挑战"。固定分块可能把两个主题各切一半，生成一个"半机器半 NLP"的无效块。

三种断点检测方法

如何定义"相似度骤降"？Notebook 中介绍了三种统计学方法：

方法 原理 直觉理解
百分位法 (Percentile) 取所有相似度的第 P 百分位作为阈值，低于该值的位置即为断点 相似度排在"最差的 10%"的相邻句对之间切开
标准差法 (Std Dev) 阈值 = 均值 − k × 标准差，低于该值即为断点 相似度比"平均水平"低了 k 个标准差的地方
四分位距法 (IQR) 阈值 = Q1 − 1.5 × IQR，利用异常值检测思路 把相似度异常低的相邻句对视为"离群点"

💻 4. 关键代码解读

下面提炼 Notebook 中最核心的代码片段，逐步解释每一步在做什么、为什么这么做。

4.1 从 PDF 提取文本

使用 PyMuPDF 库从 PDF 中逐页提取纯文本。这一步是所有 RAG 流水线的起点——你需要先把"死"的 PDF 变成"活"的字符串。

extract_text_from_pdf Python 
def extract_text_from_pdf(pdf_path):
    mypdf = fitz.open(pdf_path)
    all_text = ""
    for page in mypdf:
        all_text += page.get_text("text") + " "
    return all_text.strip()

4.2 句子分割 + 逐句 Embedding

语义分块的前提是先拆到句子粒度，再在句子之间找断点。这里用简单的 ". " 分割（实际项目中建议使用 nltk.sent_tokenize 或 spacy 的 sentence boundary detection）。

get_embedding + 句子分割 Python 
def get_embedding(text, model="text-embedding-ada-002"):
    """使用 OpenAI 的嵌入模型将文本转为向量"""
    response = client.embeddings.create(model=model, input=text)
    return np.array(response.data[0].embedding)

# 按句子分割
sentences = extracted_text.split(". ")

# 为每个句子生成 embedding
embeddings = [get_embedding(sentence) for sentence in sentences]
# → 得到 257 个句子的 embedding 向量
🤔 为什么用 text-embedding-ada-002？

这是 OpenAI 的经典嵌入模型，输出 1536 维向量，在语义相似度任务上表现优异。它能捕捉句子级别的语义信息——两句话意思越接近，向量间的余弦相似度越高。

4.3 计算相邻句子的余弦相似度

这是语义分块的核心计算：比较第 i 句和第 i+1 句的 embedding，得到一个相似度序列。

cosine_similarity + 相似度序列 Python 
def cosine_similarity(vec1, vec2):
    """余弦相似度 = 点积 / (模长之积)"""
    return np.dot(vec1, vec2) / (np.linalg.norm(vec1) * np.linalg.norm(vec2))

# 计算 256 个相邻句对的相似度
similarities = [
    cosine_similarity(embeddings[i], embeddings[i + 1])
    for i in range(len(embeddings) - 1)
]

相似度接近 1 → 两句话语义连贯；接近 0 或更低 → 话题可能发生了切换。

4.4 断点检测：百分位法

这是最关键的一步。Notebook 实现了三种方法，我们重点看百分位法：

compute_breakpoints — 核心断点检测 Python 
def compute_breakpoints(similarities, method="percentile", threshold=90):
    if method == "percentile":
        # 第 90 百分位：只有最差的 10% 相似度会被视为断点
        threshold_value = np.percentile(similarities, threshold)
    elif method == "standard_deviation":
        mean = np.mean(similarities)
        std_dev = np.std(similarities)
        threshold_value = mean - (threshold * std_dev)
    elif method == "interquartile":
        q1, q3 = np.percentile(similarities, [25, 75])
        threshold_value = q1 - 1.5 * (q3 - q1)

    # 返回所有低于阈值的索引位置
    return [i for i, sim in enumerate(similarities) if sim < threshold_value]
📐 直觉理解

想象你有一组考试成绩。百分位法的逻辑是："把分数最低的 10% 的学生挑出来"——对应到语义分块，就是把相似度最低的 10% 的相邻句对挑出来，在它们之间切一刀。

4.5 在断点处切分文本

split_into_chunks Python 
def split_into_chunks(sentences, breakpoints):
    chunks = []
    start = 0
    for bp in breakpoints:
        # 从 start 到当前断点之间的句子组成一个块
        chunks.append(". ".join(sentences[start:bp + 1]) + ".")
        start = bp + 1
    # 最后剩余的句子作为最后一个块
    chunks.append(". ".join(sentences[start:]))
    return chunks

text_chunks = split_into_chunks(sentences, breakpoints)
# → 257 个句子被分成 231 个语义块

注意：257 个句子产生了 231 个块，说明大部分块只包含 1-2 个句子。这是因为示例文本较短且话题切换频繁。在实际长文档中，每个块通常包含多个句子。

4.6 语义搜索 + LLM 生成

切块完成后，后续流程与基础 RAG 一致：为每个块生成 embedding → 用查询做余弦相似度检索 → 把 top-k 结果喂给 LLM 生成回答。

semantic_search — 检索最相关的语义块 Python 
def semantic_search(query, text_chunks, chunk_embeddings, k=5):
    query_embedding = get_embedding(query)
    similarities = [
        cosine_similarity(query_embedding, emb) for emb in chunk_embeddings
    ]
    top_indices = np.argsort(similarities)[-k:][::-1]
    return [text_chunks[i] for i in top_indices]

⚖️ 6. 优缺点与适用场景

✅ 优势

  • 保持语义完整性，避免话题被截断
  • 检索质量更高，返回的上下文更相关
  • 适应不同长度的段落，不强制统一大小
  • 三种断点方法灵活可调
  • 特别适合结构化程度低的长文本

⚠️ 局限

  • 需要为每个句子调用 Embedding API，成本高
  • 句子分割质量直接影响分块效果
  • 短文本上优势不明显（示例中 257 句 → 231 块）
  • 百分位阈值需要调参，不同文档可能需要不同设置
  • 无法处理跨段落的语义关联

适用场景

场景 推荐度 原因
长篇技术文档 / 论文 ⭐⭐⭐⭐⭐ 话题切换频繁，语义分块优势最大
法律合同 / 法规 ⭐⭐⭐⭐⭐ 条款之间边界清晰但长度不一
FAQ / 短问答对 ⭐⭐ 每条本身就很短，固定分块即可
代码仓库 ⭐⭐ 代码有自身的结构边界（函数/类），用 AST 分块更合适
对话记录 / 聊天日志 ⭐⭐⭐⭐ 话题切换频繁，但需注意对话轮次的边界
