1. 为什么需要图增强型 RAG？

传统的 RAG 管道将文档切块后存入向量数据库，检索时通过余弦相似度找到最相关的 Top-K 个片段。这种方式简单高效，但存在一个根本性局限：它假设知识是扁平的、独立的。

现实中的知识往往是高度互联的。概念之间存在因果、层级、对比、引用等复杂关系。当我们问"Transformer 如何处理序列数据，与 RNN 有何不同？"时，答案分散在多个相互关联的文本块中——仅靠向量相似度很难一次性找全。

💡 核心洞察

图增强型 RAG（Graph RAG）将知识组织为连接的图结构，每个节点是一个文本块，边表示节点间的语义关联。检索时不仅找到最相似的起点，还沿着边进行图遍历，逐步发现相关上下文。

2. 核心思想：从扁平文档到连接图

Graph RAG 的本质是将"文档集合"转化为"知识网络"：

  • 节点（Node）：每个文本块成为一个节点，携带原始文本、提取的概念列表和嵌入向量
  • 边（Edge）：当两个块共享关键概念或语义相似度超过阈值时，建立连接
  • 边权重：综合考虑语义相似度和概念重叠度，决定遍历优先级

4. 概念提取：用 LLM 构建语义节点

概念提取是 Graph RAG 区别于传统 RAG 的关键步骤。我们使用 LLM 从每个文本块中抽取 5-10 个关键概念，作为节点的"语义标签"。

import openai, json

def extract_concepts(text):
    """用 LLM 从文本块中提取关键概念"""
    prompt = f"""从以下文本中提取 5-10 个关键概念。
以 JSON 格式返回，格式为 {{"concepts": ["概念1", "概念2", ...]}}。
只返回 JSON，不要其他内容。

文本：
{text}"""

    response = openai.ChatCompletion.create(
        model="gpt-3.5-turbo",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.3,
        max_tokens=200
    )

    result = response.choices[0].message.content.strip()
    # 解析 JSON
    concepts = json.loads(result)["concepts"]
    return concepts
⚠️ 实践注意

LLM 返回的 JSON 有时格式不规范（多余的解释文字、缺少引号等），需要加入容错处理。生产环境建议使用 json_repair 库或正则表达式兜底。

提取出的概念不仅用于构建图的边，还充当了节点的"语义指纹"。两个节点之间的概念重叠度（concept overlap）是计算边权重的重要维度之一。

5. 构建知识图谱：节点、边与权重

有了概念列表和嵌入向量后，我们用 NetworkX 构建知识图谱：

import networkx as nx
from sklearn.metrics.pairwise import cosine_similarity

def build_knowledge_graph(chunks, embeddings):
    """
    构建知识图谱
    chunks: [(text, concepts), ...]
    embeddings: 每个 chunk 的嵌入向量
    """
    G = nx.Graph()

    # 添加节点
    for i, (text, concepts) in enumerate(chunks):
        G.add_node(i,
                   text=text,
                   concepts=concepts,
                   embedding=embeddings[i])

    # 计算所有节点对的相似度矩阵
    sim_matrix = cosine_similarity(embeddings)

    # 建立边：语义相似度 > 0.6 的节点对
    n = len(chunks)
    for i in range(n):
        for j in range(i + 1, n):
            sim = sim_matrix[i][j]
            if sim > 0.6:
                # 计算概念重叠度
                concepts_i = set(chunks[i][1])
                concepts_j = set(chunks[j][1])
                overlap = len(concepts_i & concepts_j) / \
                          len(concepts_i | concepts_j)

                # 边权重 = 0.7×语义相似度 + 0.3×概念重叠度
                weight = 0.7 * sim + 0.3 * overlap

                G.add_edge(i, j, weight=weight,
                           similarity=sim,
                           concept_overlap=overlap)

    return G

边权重公式

📐 权重计算

weight = 0.7 × cosine_similarity + 0.3 × concept_overlap

语义相似度占主导（70%），概念重叠作为补充（30%）。这种组合确保边既反映深层语义关联，又保留显式的概念连接。

在我们的实验中，42 个节点之间只有约 6 条边通过了 0.6 的阈值。这看似稀疏，但恰好反映了学术论文中概念之间的精确关联——并非所有文本块都高度相关。

6. 图遍历检索：从 Top-K 到 BFS 扩散

图遍历检索是 Graph RAG 的核心查询机制。与传统 Top-K 检索不同，它不仅找到最相似的节点，还沿着图的边进行广度优先搜索（BFS），逐步发现更多相关上下文。

图 2：图遍历检索示意——从 Top-K 最相似节点出发，沿边进行 BFS 扩散，逐层发现更多相关上下文

import numpy as np
from collections import deque

def traverse_graph(query, graph, embeddings, top_k=5, max_depth=3):
    """图遍历检索：从 Top-K 起点 BFS 扩散"""
    # 1. 计算查询与所有节点的相似度
    query_emb = get_embedding(query)  # 用 OpenAI 嵌入
    node_indices = list(graph.nodes)
    node_embeddings = [graph.nodes[n]['embedding'] for n in node_indices]

    similarities = cosine_similarity([query_emb], node_embeddings)[0]

    # 2. 选择 Top-K 最相似的节点作为起点
    top_indices = np.argsort(similarities)[-top_k:][::-1]
    start_nodes = [(node_indices[i], similarities[i])
                   for i in top_indices]

    # 3. BFS 遍历
    visited = set()
    traversal_path = []

    queue = deque()
    for node, sim in start_nodes:
        queue.append((node, 0, sim))  # (node, depth, score)
        visited.add(node)

    while queue:
        node, depth, score = queue.popleft()
        traversal_path.append({
            'node': node,
            'depth': depth,
            'score': score,
            'text': graph.nodes[node]['text'],
            'concepts': graph.nodes[node]['concepts']
        })

        if depth < max_depth:
            # 按边权重排序邻居
            neighbors = sorted(
                graph[node].items(),
                key=lambda x: x[1].get('weight', 0),
                reverse=True
            )
            for neighbor, edge_data in neighbors:
                if neighbor not in visited:
                    visited.add(neighbor)
                    queue.append((neighbor,
                                  depth + 1,
                                  edge_data.get('weight', 0)))

    return traversal_path

7. 图可视化与遍历路径展示

使用 networkx + matplotlib 可以将知识图谱和遍历路径可视化，直观展示检索过程：

import matplotlib.pyplot as plt
import networkx as nx

def visualize_graph_traversal(graph, traversal_path):
    """可视化知识图谱与遍历路径"""
    fig, ax = plt.subplots(figsize=(14, 10))

    # 布局
    pos = nx.spring_layout(graph, k=2, iterations=50, seed=42)

    # 遍历到的节点集合
    visited_nodes = {item['node'] for item in traversal_path}

    # 绘制所有节点（灰色）
    nx.draw_networkx_nodes(graph, pos,
                           node_color='#30363d',
                           node_size=300, alpha=0.4, ax=ax)

    # 高亮遍历路径中的节点
    nx.draw_networkx_nodes(graph, pos,
                           nodelist=list(visited_nodes),
                           node_color='#58a6ff',
                           node_size=500, alpha=0.9, ax=ax)

    # 绘制边
    edges = graph.edges(data=True)
    weights = [d.get('weight', 0.5) for _, _, d in edges]
    nx.draw_networkx_edges(graph, pos,
                           edge_color='#30363d',
                           width=[w * 3 for w in weights],
                           alpha=0.5, ax=ax)

    # 标注起始节点
    start_node = traversal_path[0]['node']
    nx.draw_networkx_nodes(graph, pos,
                           nodelist=[start_node],
                           node_color='#3fb950',
                           node_size=600, ax=ax)

    ax.set_title("Graph RAG Traversal", color='#e6edf3')
    plt.tight_layout()
    plt.savefig("graph_traversal.png",
                facecolor='#0d1117', dpi=150)
    plt.show()

8. 传统向量检索 vs 图检索

图 4：传统向量检索（左）vs 图增强检索（右）——图检索通过 BFS 遍历发现更多间接关联的上下文

🔴 传统向量检索

  • 扁平文档集合，片段之间互不关联
  • 仅依赖余弦相似度排序
  • Top-K 固定数量，可能遗漏关键上下文
  • 无法处理多跳推理问题
  • 对"比较类"和"综述类"查询效果差

🟢 图增强检索

  • 知识以网络形式组织，节点间有显式关联
  • 结合语义相似度 + 概念重叠度
  • BFS 动态扩展，自适应检索范围
  • 天然支持多跳推理和关联发现
  • 对复杂查询（比较、因果）效果更好

10. 核心代码提炼

以下是完整管道的集成函数，将上述各步骤串联起来：

def graph_rag_pipeline(pdf_path, query):
    """Graph RAG 完整管道"""

    # 1. 文本提取与分块
    text = extract_text_from_pdf(pdf_path)
    chunks = recursive_split(text, chunk_size=1000, overlap=200)
    print(f"📄 分块完成: {len(chunks)} 个块")

    # 2. 概念提取
    chunk_data = []
    for i, chunk in enumerate(chunks):
        concepts = extract_concepts(chunk)
        chunk_data.append((chunk, concepts))
        print(f"  块 {i+1}: 提取 {len(concepts)} 个概念")

    # 3. 生成嵌入
    embeddings = [get_embedding(chunk) for chunk, _ in chunk_data]

    # 4. 构建知识图谱
    G = build_knowledge_graph(chunk_data, embeddings)
    print(f"🕸️ 图构建完成: {G.number_of_nodes()} 节点, "
          f"{G.number_of_edges()} 边")

    # 5. 图遍历检索
    traversal = traverse_graph(query, G, embeddings,
                               top_k=5, max_depth=3)
    print(f"🔍 遍历完成: 访问 {len(traversal)} 个节点")

    # 6. 组装上下文并生成回答
    context_parts = []
    for item in traversal:
        context_parts.append(
            f"[Depth {item['depth']}] {item['text']}"
        )
    context = "\n\n---\n\n".join(context_parts)

    answer = generate_answer(query, context)
    return answer, traversal, G

11. 总结与展望

本篇核心收获

  • 知识图谱化：将扁平文档集合转化为连接的知识网络，每个节点携带文本、概念和嵌入三重信息
  • 概念提取：利用 LLM 从文本块中抽取关键概念，作为构建边的"语义锚点"
  • 混合边权重：0.7×语义相似度 + 0.3×概念重叠，兼顾深层语义和显式概念关联
  • 图遍历检索：从 Top-K 起点进行 BFS 扩散，按边权重优先探索高相关邻居
  • 多跳推理：图结构天然支持跨文本块的关联发现，对复杂查询效果显著
🚀 进阶方向

Graph RAG 仍有大量优化空间：

  • 实体级图谱：将节点从文本块细化为实体（人物、概念、方法），边表示实体间关系
  • 社区检测：使用 Louvain 等算法发现图中的主题社区，生成社区摘要
  • 动态图更新：新文档加入时增量更新图结构，而非全量重建
  • 混合检索：结合图遍历与传统向量检索，取两者之长
