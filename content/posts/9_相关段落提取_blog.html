1. 引言：Top-K 检索的局限

在传统的 RAG 管道中，检索阶段通常返回与查询最相似的 Top-K 个孤立块。这些块虽然在语义上与查询相关，但它们在原始文档中的位置可能相距甚远，导致上下文断裂。

Top-K 的问题

假设查询涉及一个跨越多个段落的话题，Top-K 可能只命中其中的第 3、7、15 块 —— 它们之间的过渡信息全部丢失，LLM 拿到的是一堆"碎片"而非连贯叙述。

相关段落提取（Relevant Segment Extraction, RSE）正是为了解决这一问题而提出的。它不再返回孤立的块，而是找到最佳的连续文本段落，为 LLM 提供更连贯的上下文。

2. RSE 核心思想

RSE 的关键洞察是：相关信息往往在文档中聚集出现。如果一个块与查询高度相关，那么它附近的块也很可能包含有用信息。

RSE 的核心流程可以概括为三步：

  1. 计算块值：为每个块赋予一个"价值"分数（相关性 - 惩罚）
  2. 寻找最佳段落：用变体最大子数组和算法找到价值最高的连续段落
  3. 重构段落：将相邻块拼接成完整文本

4. 计算块值（Chunk Values）

RSE 的第一步是为文档中的每个块计算一个"价值"分数。这个分数综合考虑了块与查询的相关性以及一个惩罚项：

核心公式

chunk_value[i] = relevance_score[i] - irrelevant_chunk_penalty

其中 irrelevant_chunk_penalty 默认值为 0.2。这意味着只有相关性分数超过 0.2 的块才具有正价值，其余块被视为"噪声"并赋予负值。

def calculate_chunk_values(query, chunks, vector_store,
                           irrelevant_chunk_penalty=0.2):
    """通过结合相关性和惩罚来计算每个块的价值。"""
    # 1. 创建查询嵌入
    query_embedding = create_embeddings([query])[0]

    # 2. 全量检索：获取所有块的相关性分数
    num_chunks = len(chunks)
    results = vector_store.search(query_embedding, top_k=num_chunks)

    # 3. 构建索引→分数的映射
    relevance_scores = {
        r["metadata"]["chunk_index"]: r["score"] for r in results
    }

    # 4. 计算块值 = 相关性分数 - 惩罚
    chunk_values = []
    for i in range(num_chunks):
        score = relevance_scores.get(i, 0.0)
        value = score - irrelevant_chunk_penalty
        chunk_values.append(value)

    return chunk_values

这一步的关键在于 irrelevant_chunk_penalty 参数。它充当了一个"门槛"：

  • 相关性 > 0.2 的块 → 正价值（值得保留）
  • 相关性 < 0.2 的块 → 负价值（应当跳过）

5. 寻找最佳段落

有了块值之后，RSE 使用一种变体最大子数组和算法来找到价值最高的连续段落。这类似于经典的 Kadane 算法，但增加了多个约束条件：

参数默认值含义
max_segment_length20单个段落允许包含的最大块数
total_max_length30所有段落合计的最大块数
min_segment_value0.2段落被采纳的最低价值阈值
 
def find_best_segments(chunk_values, max_segment_length=20,
                       total_max_length=30, min_segment_value=0.2):
    """使用最大子数组和算法的变体找到最佳段落。"""
    best_segments = []
    segment_scores = []
    total_included_chunks = 0

    while total_included_chunks < total_max_length:
        best_score = min_segment_value
        best_segment = None

        for start in range(len(chunk_values)):
            # 跳过已被选中的起始位置
            if any(start >= s[0] and start < s[1] for s in best_segments):
                continue

            for length in range(1, min(max_segment_length,
                                       len(chunk_values) - start) + 1):
                end = start + length
                # 跳过与已选段落重叠的区间
                if any(end > s[0] and end <= s[1] for s in best_segments):
                    continue

                segment_value = sum(chunk_values[start:end])
                if segment_value > best_score:
                    best_score = segment_value
                    best_segment = (start, end)

        if best_segment:
            best_segments.append(best_segment)
            segment_scores.append(best_score)
            total_included_chunks += best_segment[1] - best_segment[0]
        else:
            break

    return sorted(best_segments, key=lambda x: x[0]), segment_scores
算法直觉

该算法穷举所有可能的连续区间，找出价值最高的段落。每找到一个段落后就将其"锁定"，然后在剩余空间中继续搜索下一个最佳段落，直到达到总长度限制或没有满足阈值的新段落为止。

6. 段落重构与格式化

找到最佳段落的索引范围后，RSE 将相邻块拼接成连续文本：

def reconstruct_segments(chunks, best_segments):
    """根据块索引重构文本段落。"""
    reconstructed = []
    for start, end in best_segments:
        segment_text = " ".join(chunks[start:end])
        reconstructed.append({
            "text": segment_text,
            "segment_range": (start, end),
        })
    return reconstructed


def format_segments_for_context(segments):
    """将段落格式化为 LLM 的上下文字符串。"""
    context = []
    for i, seg in enumerate(segments):
        header = f"SEGMENT {i+1} (Chunks {seg['segment_range'][0]}"
        header += f"-{seg['segment_range'][1]-1}):"
        context.append(header)
        context.append(seg['text'])
        context.append("-" * 80)
    return "\n\n".join(context)

格式化后的上下文带有清晰的段落标记和块范围信息，方便 LLM 理解信息的来源位置。

7. 完整 RSE 管道

将所有步骤串联起来，形成端到端的 RAG + RSE 管道：

def rag_with_rse(pdf_path, query, chunk_size=800,
                 irrelevant_chunk_penalty=0.2):
    """完整的 RAG 管道 + 相关段落提取。"""
    print("\n=== STARTING RAG WITH RELEVANT SEGMENT EXTRACTION ===")
    print(f"Query: {query}")

    # Step 1: 文档处理 → 分块 + 嵌入 + 向量存储
    chunks, vector_store, doc_info = process_document(pdf_path, chunk_size)

    # Step 2: 计算每个块的价值
    chunk_values = calculate_chunk_values(
        query, chunks, vector_store, irrelevant_chunk_penalty
    )

    # Step 3: 寻找最佳连续段落
    best_segments, scores = find_best_segments(
        chunk_values,
        max_segment_length=20,
        total_max_length=30,
        min_segment_value=0.2
    )

    # Step 4: 重构段落文本
    segments = reconstruct_segments(chunks, best_segments)

    # Step 5: 格式化上下文 → 送入 LLM
    context = format_segments_for_context(segments)
    response = generate_response(query, context)

    return {"query": query, "segments": segments, "response": response}

RSE 优势

  • 保持上下文连续性
  • 相邻信息自然衔接
  • 适合需要前后文的查询
  • 减少信息碎片化

RSE 劣势

  • 可能引入过多不相关信息
  • 段落边界不够精确
  • 在信息分散的查询上表现不如 Top-K
  • 计算开销更大（需全量检索）

9. 实验结果与分析

实验设置

  • 文档：2024年AI行业报告.pdf
  • 分块参数：chunk_size=800, overlap=0（非重叠）
  • 总块数：35 个块
  • 查询："中国政府对AI大模型发展有哪些支持政策？"

RSE 检索结果

RSE 算法找到了 2 个段落：

值得注意

RSE 几乎检索了全部 35 个块（20 + 15 = 35），这意味着在这个查询上，算法认为整篇文档都具有一定的相关性。这既是 RSE 的特点，也是它的潜在问题 —— 当惩罚系数设置较低时，RSE 倾向于返回大段连续文本。

LLM 评估对比

使用 GPT-4o 对两种方法的回答进行评估，结果如下：

评估维度标准 Top-KRSE
准确性和全面性更好稍逊
回答用户问题的程度更好信息广度不足
无关信息控制更精简内容略冗长
结论

在这个特定查询上，标准 Top-K 检索表现更好。原因是该查询涉及多个不同城市和不同维度的政策信息，信息分布较为分散。标准 Top-K 能够精准挑选最相关的块，而 RSE 由于追求连续性，引入了大量中间地带的冗余信息。

RSE 的适用场景

尽管在本次实验中 Top-K 胜出，RSE 在以下场景中仍有独特优势：

  • 叙事性文档：如法律条文、技术手册等，上下文高度依赖前后文
  • 局部聚焦查询：当答案集中在文档某个区域时，RSE 能精准锁定并保留完整上下文
  • 需要推理的查询：当答案需要综合相邻多段信息推导时，连续段落优于碎片

10. 总结与展望

相关段落提取（RSE）提供了一种不同于传统 Top-K 的检索思路：

  • 通过 块值 = 相关性 - 惩罚 的转换，将检索问题转化为最大子数组和问题
  • 通过 连续段落 而非孤立块来保持上下文连贯性
  • 关键参数 irrelevant_chunk_penalty 控制着"严格筛选"与"宽松召回"之间的平衡
