1. 问题动机：向量相似 ≠ 问答相关

在前面的篇章中，我们已经构建了基础的 RAG 管道：将文档切块、生成嵌入向量、通过余弦相似度检索最相关的文本块。但实际运行中，一个核心痛点逐渐浮现：

核心问题

向量空间中的"相似"并不等于"能回答问题"。一个文本块可能在主题上与查询高度相关（余弦相似度很高），但其中并不包含可直接摘录的答案句；而真正能回答问题的块可能因为切块边界或表述差异被排在 Top-k 之外。

例如，查询"中国政府对 AI 大模型发展有哪些支持政策？"时，向量检索可能返回大量讨论"AI 政策"的文本块，但其中有些只是泛泛提及政策背景，有些则包含了具体的城市级政策细节。我们需要一道"二次过滤"来区分谁更有价值。

这就是重排序（Reranking）的角色——在初始检索之后、答案生成之前，插入一个评分与排序步骤，确保最终进入 LLM 上下文的是真正"能回答问题的"文本块。

2. 重排序流程总览

重排序的核心思想可以用一句话概括："先广撒网，再精挑选"。初始检索取回较多的候选（如 Top-10），然后通过某种评分机制对每个候选重新打分，最后只取评分最高的 Top-N 进入生成阶段。

关键设计决策

初始检索的 k=10 要大于最终使用的 top_n=3。这为后续的"纠错"留出了空间——即使向量检索把某些相关块排在了第 5~8 位，重排序仍有机会将它们提到前面。

3. 两种重排方法对比

本系列实现了两种截然不同的重排序策略，分别代表了"重量级"与"轻量级"两条路线：

基于 LLM 的重排序

  • 原理：调用 gpt-4o 对每个文档独立评分（0-10），评估其对查询的回答能力
  • 优势：深度语义理解，能判断"虽不相似但能回答问题"的文档
  • 代价：每个文档一次 API 调用，延迟与费用线性增长
  • 适用场景：对质量要求高、候选数量可控（10-20 个）

基于关键词的重排序

  • 原理：用 jieba 分词提取查询关键词，根据出现位置、频率等规则加分
  • 优势：无需额外 API 调用，速度快、成本低、可解释
  • 代价：无法理解同义改写，依赖精确词匹配
  • 适用场景：成本敏感、中文关键词明显的场景

5. 代码解读：基于 LLM 的重排序

LLM 重排序的核心思路是 "LLM-as-a-Judge"——让大模型充当裁判，逐一对每个候选文档进行相关性评分。

def rerank_with_llm(query, results, top_n=3, model="gpt-4o"):
    """
    使用 LLM 进行相关性评分来重新排序搜索结果。

    参数:
        query (str): 用户查询
        results (List[Dict]): 初始搜索结果
        top_n (int): 重新排序后返回的结果数量
        model (str): 用于评分的模型

    返回:
        List[Dict]: 重新排序后的结果
    """
    scored_results = []

    # 系统提示：定义评分标准，要求 LLM 只返回一个整数分数
    system_prompt = """你是一名擅长评估文档与查询相关性的专家。
你的任务是根据文档对查询的回答程度，对文档进行0到10分的打分。

评分标准：
- 0-2分：文档与查询完全无关
- 3-5分：文档包含部分相关信息，但未能直接回答查询
- 6-8分：文档相关，能够部分回答查询
- 9-10分：文档高度相关，能够直接回答查询

你必须只回复一个0到10之间的整数分数，不要包含任何其他文本。"""

    for i, result in enumerate(results):
        user_prompt = f"""查询：{query}

文档内容：
{result['text']}

请根据上述查询，对该文档与查询的相关性进行0到10分的打分："""

        # 调用 LLM，temperature=0 确保评分稳定可复现
        response = client.chat.completions.create(
            model=model,
            temperature=0,
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": user_prompt}
            ]
        )

        score_text = response.choices[0].message.content.strip()

        # 用正则提取 0-10 的整数分数
        score_match = re.search(r'\b(10|[0-9])\b', score_text)
        if score_match:
            score = float(score_match.group(1))
        else:
            # 回退方案：用向量相似度 × 10 作为替代分数
            score = result["similarity"] * 10

        scored_results.append({
            "text": result["text"],
            "metadata": result["metadata"],
            "similarity": result["similarity"],
            "relevance_score": score
        })

    # 按相关性分数降序排列，取前 top_n
    reranked_results = sorted(
        scored_results, key=lambda x: x["relevance_score"], reverse=True
    )
    return reranked_results[:top_n]
设计要点

temperature=0：评分任务需要确定性输出，随机性会引入排序噪声。
正则回退：当 LLM 未严格遵循"只返回数字"的指令时，正则解析可能失败。此时回退到 similarity * 10，将余弦相似度（0~1）映射到 0~10 的量纲，保持排序不至于完全崩溃。

6. 代码解读：基于关键词的重排序

关键词重排序是一种零成本的替代方案——不依赖额外 API 调用，而是通过 jieba 中文分词提取查询中的关键词，并根据它们在文档中的出现与否、位置和频率来加分。

import jieba

def rerank_with_keywords(query, results, top_n=3):
    """
    基于中文关键词分词和位置的简单重排序方法。

    参数:
        query (str): 用户查询（中文）
        results (List[Dict]): 初始搜索结果
        top_n (int): 重排序后返回的结果数量

    返回:
        List[Dict]: 重排序后的结果
    """
    # 用 jieba 分词，过滤掉单字词（通常是停用词）
    keywords = [word for word in jieba.lcut(query) if len(word) > 1]

    scored_results = []

    for result in results:
        document_text = result["text"]

        # 基础分数：保留向量检索信号，权重 0.5
        base_score = result["similarity"] * 0.5

        # 关键词加分
        keyword_score = 0
        for keyword in keywords:
            if keyword in document_text:
                # 命中加分：+0.1
                keyword_score += 0.1

                # 位置加分：出现在文档前 1/4 额外 +0.1
                first_position = document_text.find(keyword)
                if 0 <= first_position < len(document_text) / 4:
                    keyword_score += 0.1

                # 频率加分：每次出现 +0.05，上限 +0.2
                frequency = document_text.count(keyword)
                keyword_score += min(0.05 * frequency, 0.2)

        # 最终分数 = 基础分 + 关键词加分
        final_score = base_score + keyword_score

        scored_results.append({
            "text": result["text"],
            "metadata": result["metadata"],
            "similarity": result["similarity"],
            "relevance_score": final_score
        })

    reranked_results = sorted(
        scored_results, key=lambda x: x["relevance_score"], reverse=True
    )
    return reranked_results[:top_n]

评分公式解析

关键词重排序的最终分数由以下公式决定：

评分公式

final_score = similarity × 0.5 + keyword_score

其中 keyword_score 由三部分组成：

  • 命中分：每个关键词在文档中出现 → +0.1
  • 位置分：关键词出现在文档前 25% → 额外 +0.1
  • 频率分：每次出现 +0.05，单词上限 +0.2

这种设计的直觉是：如果一个关键词不仅出现了，而且出现在文档开头（通常是主题句的位置），并且多次出现，那这个文档大概率是在重点讨论这个主题。

7. 代码解读：完整 RAG + 重排序管道

将重排序集成到 RAG 管道中非常简洁——只需在初始检索和答案生成之间插入一个分支：

def rag_with_reranking(query, vector_store, reranking_method="llm",
                        top_n=3, model="gpt-4o"):
    """
    完整的 RAG 管道，包含重排序步骤。

    参数:
        query (str): 用户查询
        vector_store (SimpleVectorStore): 向量存储
        reranking_method (str): 重排序方法（'llm' 或 'keywords'）
        top_n (int): 重排序后返回的结果数量
        model (str): 回复生成模型

    返回:
        Dict: 包括查询、上下文和回复的结果字典
    """
    # 1. 创建查询嵌入
    query_embedding = create_embeddings(query)

    # 2. 初始检索：取比最终需要更多的候选（k=10）
    initial_results = vector_store.similarity_search(query_embedding, k=10)

    # 3. 根据方法选择重排序策略
    if reranking_method == "llm":
        reranked_results = rerank_with_llm(
            query, initial_results, top_n=top_n
        )
    elif reranking_method == "keywords":
        reranked_results = rerank_with_keywords(
            query, initial_results, top_n=top_n
        )
    else:
        # 无重排序，直接取初始检索的前 N 个
        reranked_results = initial_results[:top_n]

    # 4. 拼接上下文（用分隔符降低模型混读概率）
    context = "\n\n===\n\n".join(
        [result["text"] for result in reranked_results]
    )

    # 5. 基于上下文生成回复
    response = generate_response(query, context, model)

    return {
        "query": query,
        "reranking_method": reranking_method,
        "initial_results": initial_results[:top_n],
        "reranked_results": reranked_results,
        "context": context,
        "response": response
    }
管道设计亮点

统一接口：reranking_method 参数支持 "llm"、"keywords"、"none" 三种模式，方便 A/B 对比实验。
上下文分隔符：使用 === 分隔不同文本块，降低 LLM 将两段无关文本混读的概率——这是一个简单但有效的工程技巧。

9. LLM 评估结论

我们使用 GPT-4o 作为"裁判"，对标准检索与 LLM 重排序的结果进行了元评估。以下是评估的核心结论：

元评估报告摘要

评估维度 结论
上下文相关性 两种方式基本一致，均详细列出了各地政策
答案准确性 LLM 重排更优——提供了"全栈国产化"等标准检索未提及的细节
答案全面性 LLM 重排更全面——在北京政策描述中展示了多层次支持措施
总体表现 重排序方式表现更好，提供了更详细和全面的答案
关键发现

重排序的核心价值不在于"找到全新的信息"，而在于调整信息的优先级。同样的 10 个候选文档，经过重排序后，真正包含细节的文本块被提到了最前面，使得 LLM 在生成回答时能优先利用这些高质量证据。

10. 总结与展望

本篇核心收获

  1. 重排序是 RAG 质量提升的关键环节：在初始检索后加入二次过滤，可以显著提高进入生成阶段的上下文质量。
  2. 两种互补的策略：LLM 重排序质量更高但成本大，关键词重排序速度快但理解有限。实际生产中可以根据场景灵活选择或组合使用。
  3. "先广后精"的设计模式：初始检索取大集合（k=10），重排序后取小集合（top_n=3），在召回率与精确度之间取得平衡。
  4. 评估同样重要：通过 LLM 元评估，我们可以系统性地比较不同检索策略的效果，指导参数调优。

进阶方向

  • 专用 Reranker 模型：如 Cohere Rerank、BGE-Reranker、Cross-Encoder 等，在速度和质量之间取得更好的平衡
  • 混合检索 + 重排序：结合 BM25 关键词检索与向量检索，再用 Reranker 统一排序
  • 批量化 LLM 评分：将多个文档放入一次 prompt 中打分，减少 API 调用次数
  • 学习排序（Learning to Rank）：用标注数据训练专用的排序模型
