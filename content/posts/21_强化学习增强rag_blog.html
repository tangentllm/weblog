一、引言：为什么用强化学习增强 RAG？

在前面的 20 篇中，我们系统地探索了 RAG 管道的各种优化技术——从基础检索、语义分块，到自适应 RAG、动态纠正 RAG。这些方法大多依赖手工设计的规则来决定何时检索、如何重写查询、怎样过滤上下文。

但一个根本性的问题是：这些决策能否自动学习？

强化学习（Reinforcement Learning, RL）为这个问题提供了一个优雅的答案。在 RL-RAG 框架中，我们将 RAG 管道建模为一个序贯决策过程：一个 Agent 在每一步根据当前状态选择动作（重写查询、扩展上下文、过滤噪声、生成回复），环境返回奖励信号，Agent 通过不断试错来学习最优策略。

核心思想：与其手工设计 RAG 管道的每一步决策，不如让 Agent 自己通过与环境交互来学习——什么情况下该重写查询？什么时候上下文已经足够？什么时候该停止检索直接生成？

本篇作为系列的最终篇，将 RL 引入 RAG 管道优化，既是对前文所有技术的统一视角——将检索、过滤、生成视为可学习的策略——也为整个系列画上一个面向未来的句号。

二、RL 框架定义：状态、动作与奖励

将 RAG 管道建模为马尔可夫决策过程（MDP），需要定义三个核心要素：

2.1 状态表示（State）

状态捕获了 Agent 在每一步决策时所掌握的全部信息：

def define_state(query, context_chunks, previous_responses, previous_rewards):
    """
    定义 RL Agent 的状态表示
    State = {
        original_query: 原始查询文本
        current_query:  当前查询（可能已被重写）
        context:        当前检索到的上下文片段列表
        previous_responses: 历史生成的回复
        previous_rewards:   历史获得的奖励值
    }
    """
    state = {
        "original_query": query,
        "current_query": query,  # 初始时等于原始查询
        "context": context_chunks,
        "previous_responses": previous_responses,
        "previous_rewards": previous_rewards,
    }
    return state

2.2 动作空间（Action Space）

Agent 在每一步可以选择 4 种动作之一：

def define_action_space():
    """定义 Agent 可用的动作空间"""
    return [
        "rewrite_query",      # 用 LLM 重写查询
        "expand_context",     # 检索额外上下文片段
        "filter_context",     # 过滤不相关的上下文片段
        "generate_response",  # 基于当前上下文生成最终回复
    ]

2.3 奖励函数（Reward）

奖励信号指导 Agent 学习——我们使用生成回复与标准答案之间的嵌入余弦相似度作为奖励：

from sklearn.metrics.pairwise import cosine_similarity

def calculate_reward(response, ground_truth):
    """
    计算奖励：回复嵌入与标准答案嵌入的余弦相似度
    范围 [-1, 1]，值越大表示回复质量越高
    """
    response_embedding = embed(response)
    truth_embedding = embed(ground_truth)
    similarity = cosine_similarity(
        [response_embedding],
        [truth_embedding]
    )[0][0]
    return similarity
为什么用余弦相似度？嵌入空间的余弦相似度能捕获语义层面的相似性，比简单的字符串匹配更能反映回复的实际质量。即使措辞不同，只要语义接近标准答案，就能获得高奖励。

三、四种核心动作详解

✎

rewrite_query

使用 LLM 将当前查询重写为更适合检索的形式。可消除歧义、补充关键词、调整表述。通常在第一步执行，当 Agent 尚无历史回复时触发。

🔍

expand_context

用当前查询检索额外的上下文片段，扩充 Agent 的知识库。当奖励低于阈值（<0.7）时触发，表示当前上下文不足以生成高质量回复。

📋

filter_context

过滤掉不相关的上下文片段，减少噪声干扰。当上下文片段超过 5 块时触发，防止信息过载影响生成质量。

💬

generate_response

基于当前上下文生成最终回复。这是终止动作——执行后本轮结束，计算奖励。Agent 在其他条件不满足时默认选择此动作。

整个系统的运行流程如下：

  1. 初始化：接收用户查询，构建初始状态
  2. 策略决策：Agent 根据当前状态和 epsilon-greedy 策略选择动作
  3. 执行动作：在 RAG 管道中执行选定动作，更新状态
  4. 计算奖励：如果执行了 generate_response，计算回复与标准答案的余弦相似度
  5. 迭代：重复步骤 2-4，直到生成回复或达到最大步数
  6. 策略更新：根据累积奖励调整策略参数

五、核心代码实现

5.1 策略网络：epsilon-greedy + 启发式规则

策略网络是 Agent 的"大脑"，决定在给定状态下选择哪个动作。我们采用 epsilon-greedy 策略：以 1-epsilon 的概率按启发式规则选择（利用），以 epsilon 的概率随机选择（探索）。

import random

def policy_network(state, action_space, epsilon=0.2):
    """
    策略网络：epsilon-greedy + 启发式规则

    参数:
        state: 当前状态字典
        action_space: 可用动作列表
        epsilon: 探索率（0.2 = 20% 随机探索）
    返回:
        选定的动作字符串
    """
    # epsilon-greedy: 以 epsilon 概率随机探索
    if random.random() < epsilon:
        return random.choice(action_space)

    # 启发式规则（利用）
    # 规则 1: 无历史回复 → 先重写查询
    if not state["previous_responses"]:
        return "rewrite_query"

    # 规则 2: 最近奖励 < 0.7 → 扩展上下文
    if state["previous_rewards"] and state["previous_rewards"][-1] < 0.7:
        return "expand_context"

    # 规则 3: 上下文片段 > 5 → 过滤噪声
    if len(state["context"]) > 5:
        return "filter_context"

    # 规则 4: 其他情况 → 生成回复
    return "generate_response"
epsilon 的权衡：epsilon 过大，Agent 过多随机探索，训练不稳定；epsilon 过小，Agent 过早收敛到次优策略。实践中常用 epsilon 衰减策略，从 0.3 逐步降到 0.05。

5.2 单步 RL 执行

def rl_step(state, action_space, ground_truth):
    """
    执行一步 RL 交互

    返回: (new_state, action, reward, done)
    """
    # 1. 策略网络选择动作
    action = policy_network(state, action_space)

    # 2. 执行动作，更新状态
    new_state = state.copy()
    reward = 0.0
    done = False

    if action == "rewrite_query":
        new_state["current_query"] = llm_rewrite(state["current_query"])

    elif action == "expand_context":
        new_chunks = retrieve(state["current_query"], top_k=3)
        new_state["context"] = state["context"] + new_chunks

    elif action == "filter_context":
        new_state["context"] = filter_by_relevance(
            state["current_query"],
            state["context"],
            threshold=0.5
        )

    elif action == "generate_response":
        response = generate(state["current_query"], state["context"])
        reward = calculate_reward(response, ground_truth)
        new_state["previous_responses"].append(response)
        new_state["previous_rewards"].append(reward)
        done = True

    return new_state, action, reward, done

5.3 训练循环

def training_loop(query_text, ground_truth, num_episodes=100, max_steps=10):
    """
    RL-RAG 训练循环

    参数:
        query_text: 训练查询
        ground_truth: 标准答案
        num_episodes: 训练轮数（默认 100）
        max_steps: 每轮最大步数（默认 10）
    返回:
        训练历史记录（每轮的奖励）
    """
    action_space = define_action_space()
    history = []

    for episode in range(num_episodes):
        # 初始化状态
        initial_context = retrieve(query_text, top_k=3)
        state = define_state(
            query=query_text,
            context_chunks=initial_context,
            previous_responses=[],
            previous_rewards=[]
        )

        total_reward = 0.0
        step_count = 0

        for step in range(max_steps):
            state, action, reward, done = rl_step(
                state, action_space, ground_truth
            )
            total_reward += reward
            step_count += 1

            if done:
                break

        history.append({
            "episode": episode + 1,
            "total_reward": total_reward,
            "steps": step_count,
        })

        if (episode + 1) % 20 == 0:
            avg = sum(h["total_reward"] for h in history[-20:]) / 20
            print(f"Episode {episode+1}/{num_episodes} | "
                  f"Avg Reward (last 20): {avg:.4f}")

    return history

八、为什么 RL 未显著提升？深度分析

实验结果显示 RL-RAG 的余弦相似度（0.9083）反而略低于 Simple RAG（0.9358），下降了 2.75%。这看似令人失望，但背后有深刻的原因：

8.1 Simple RAG 已经足够好

对于事实性明确、知识边界清晰的查询（如量子比特数学表示），标准的检索-生成管道已经能精准命中相关文档。此时引入额外的决策步骤（重写、过滤）反而可能引入噪声或偏离原始查询意图。

8.2 探索带来的不稳定性

epsilon-greedy 策略的探索机制意味着 Agent 在推理时仍有一定概率选择次优动作。在训练不足（仅 100 轮）的情况下，策略尚未完全收敛。

8.3 RL-RAG 的真正优势场景

RL-RAG 更适合以下场景：
  • 复杂多跳查询：需要多次检索、逐步推理的问题
  • 歧义查询：需要动态澄清和重写才能准确检索
  • 噪声文档集：需要智能过滤大量不相关片段
  • 长对话：需要根据对话历史动态调整检索策略

8.4 改进方向

  • 增加训练轮数：100 轮可能不足以让策略充分收敛
  • epsilon 衰减：从 0.3 逐步降到 0.05，平衡探索与利用
  • 更丰富的奖励函数：结合事实准确率、连贯性、完整性等多维指标
  • PPO / DQN 等高级算法：替代简单的 epsilon-greedy，学习更精细的策略
  • 在更难的基准上测试：如 HotpotQA（多跳）、AmbigQA（歧义）等

十、结语与展望

从第 1 篇的基础 RAG 到第 21 篇的强化学习增强 RAG，我们一起走过了整个 RAG 技术栈。回顾这段旅程，有几个关键洞察：

系列核心洞察：
  1. 分块策略是地基：语义分块 + 合适的粒度决定了检索质量的上限
  2. 检索是瓶颈：查询转换、重排序、命题分块都在解决"找到对的文档"这个问题
  3. 上下文是艺术：压缩、过滤、提取——在有限窗口内最大化信息密度
  4. 自适应是未来：不同查询需要不同策略，一刀切的管道不是最优解
  5. 学习是终极目标：从手工规则到 RL 自动学习，RAG 正在走向自主优化

RL-RAG 虽然在简单查询上未能超越 Simple RAG，但它代表了一个重要的方向：让 RAG 管道从"被设计"走向"自我进化"。随着更强大的 RL 算法（PPO、RLHF）、更丰富的奖励信号、更大规模的训练数据，我们有理由相信学习型 RAG 将在复杂场景中展现巨大优势。
