1. 为什么需要动态纠正？

在标准 RAG 管道中，检索到的文档会被无条件地传递给生成模型。但现实中，检索结果的质量参差不齐：

  • 向量相似度 ≠ 语义相关性（高分文档可能答非所问）
  • 知识库可能根本不包含用户问题的答案
  • 部分相关 ≠ 完全无关，需要差异化处理
⚠️ 标准 RAG 的盲区

标准 RAG 对检索结果"来者不拒"——即使检索到的文档完全不相关，它仍然会基于这些噪声生成回复，导致幻觉或误导性回答。

Corrective RAG（CRAG） 的核心思想是：在检索之后、生成之前，增加一个质量评估环节，根据评估结果动态调整信息获取策略。

2. 什么是 CRAG？

CRAG（Corrective RAG）是一种自适应检索增强生成框架，由 Ma et al. (2024) 提出。它在传统 RAG 管道中引入了一个检索评估器（Retrieval Evaluator），能够：

  1. 对每个检索到的文档进行相关性评分（0-1 分）
  2. 根据评分结果动态决策：使用本地文档、转向网络搜索、或两者结合
  3. 对获取的知识进行精炼，提取关键信息

CRAG 的本质：让 RAG 系统从"被动接受检索结果"升级为"主动判断信息质量"。

💡 阈值选择说明

默认阈值 0.3 和 0.7 来自原论文的实验调优。在实际部署中，可以根据业务场景调整：

  • 保守策略：降低高阈值（如 0.6），更多触发网络搜索
  • 激进策略：提高低阈值（如 0.4），更倾向使用本地文档
  • 领域适配：专业领域可降低低阈值，因为向量检索在专业术语上可能偏低

5. 核心代码实现

5.1 文档相关性评估

CRAG 的核心是评估函数——使用 LLM 判断文档与查询的相关性：

Pythonfrom langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

def evaluate_document_relevance(query: str, document: str) -> float:
    """
    使用 LLM 评估文档与查询的相关性。
    返回 0-1 之间的相关性分数。
    """
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

    prompt = ChatPromptTemplate.from_messages([
        ("system", """你是一个文档相关性评估专家。
请评估以下文档与用户查询的相关程度。
返回一个 0 到 1 之间的浮点数：
- 1.0 = 完全相关，直接回答问题
- 0.7 = 高度相关，包含有用信息
- 0.3 = 部分相关，有一些联系
- 0.0 = 完全不相关

只返回数字，不要其他内容。"""),
        ("human", "查询：{query}\n\n文档：{document}\n\n相关性评分：")
    ])

    chain = prompt | llm
    response = chain.invoke({
        "query": query,
        "document": document
    })

    try:
        score = float(response.content.strip())
        return max(0.0, min(1.0, score))  # 限制在 [0, 1]
    except ValueError:
        return 0.0

5.2 DuckDuckGo 网络搜索

当本地文档不够用时，CRAG 转向网络搜索获取补充信息：

Pythonfrom duckduckgo_search import DDGS

def duck_duck_go_search(query: str, num_results: int = 3) -> str:
    """
    使用 DuckDuckGo 进行网络搜索。
    返回搜索结果文本。
    """
    with DDGS() as ddgs:
        results = list(ddgs.text(query, max_results=num_results))

    if not results:
        return ""

    # 拼接搜索结果
    combined = []
    for r in results:
        combined.append(f"标题：{r['title']}\n内容：{r['body']}")

    return "\n\n---\n\n".join(combined)

5.3 查询重写

原始查询可能不适合直接用于搜索，需要重写为更高效的搜索查询：

Pythondef rewrite_search_query(query: str) -> str:
    """
    重写用户查询，使其更适合网络搜索。
    移除口语化表达，提取核心关键词。
    """
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

    prompt = ChatPromptTemplate.from_messages([
        ("system", """你是一个搜索查询优化专家。
将用户的自然语言查询重写为更适合搜索引擎的简洁查询。
保持核心语义，去除冗余词汇。
只返回重写后的查询，不要其他内容。"""),
        ("human", "原始查询：{query}\n\n重写后的查询：")
    ])

    chain = prompt | llm
    response = chain.invoke({"query": query})
    return response.content.strip()

5.4 知识精炼

从网络搜索或本地文档中提取关键知识点：

Pythondef refine_knowledge(text: str) -> str:
    """
    用 LLM 精炼知识，提取关键要点（bullet points）。
    """
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

    prompt = ChatPromptTemplate.from_messages([
        ("system", """你是一个知识精炼专家。
从提供的文本中提取关键信息，以简洁的要点形式呈现。
每个要点一行，使用 • 开头。
只保留与问题直接相关的信息。"""),
        ("human", "请精炼以下文本的关键信息：\n\n{text}")
    ])

    chain = prompt | llm
    response = chain.invoke({"text": text})
    return response.content.strip()

5.5 完整 CRAG 管道

将所有组件整合为完整的 CRAG 处理流程：

Pythondef crag_process(
    query: str,
    vector_store,
    k: int = 3
) -> str:
    """
    完整的 CRAG 处理管道。

    1. 检索 Top-K 文档
    2. 评估每个文档的相关性
    3. 根据最高分决定策略
    4. 必要时执行网络搜索
    5. 精炼知识并生成回复
    """
    # ── Step 1: 检索 ──
    docs = vector_store.similarity_search(query, k=k)
    print(f"📚 检索到 {len(docs)} 个文档")

    # ── Step 2: 评估 ──
    scores = []
    for i, doc in enumerate(docs):
        score = evaluate_document_relevance(query, doc.page_content)
        scores.append(score)
        print(f"   文档 {i+1} 相关性: {score:.2f}")

    max_score = max(scores) if scores else 0
    best_doc_idx = scores.index(max_score)
    print(f"📊 最高相关性分数: {max_score:.2f}")

    # ── Step 3: 决策 ──
    knowledge = ""

    if max_score >= 0.7:
        # 路径 A：高相关性 → 直接使用本地文档
        print("✅ 路径 A：高相关性，使用本地文档")
        knowledge = docs[best_doc_idx].page_content

    elif max_score < 0.3:
        # 路径 C：低相关性 → 完全转向网络搜索
        print("🌐 路径 C：低相关性，转向网络搜索")
        rewritten = rewrite_search_query(query)
        print(f"   重写查询: {rewritten}")
        web_results = duck_duck_go_search(rewritten)
        knowledge = refine_knowledge(web_results)

    else:
        # 路径 B：中等相关性 → 本地 + 网络
        print("🔄 路径 B：中等相关性，混合策略")
        local_knowledge = docs[best_doc_idx].page_content
        rewritten = rewrite_search_query(query)
        web_results = duck_duck_go_search(rewritten)
        web_knowledge = refine_knowledge(web_results)
        knowledge = f"本地知识：\n{local_knowledge}\n\n网络补充：\n{web_knowledge}"

    # ── Step 4: 生成回复 ──
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
    final_prompt = ChatPromptTemplate.from_messages([
        ("system", "基于以下知识回答用户问题。注明信息来源。"),
        ("human", "问题：{query}\n\n知识：\n{knowledge}")
    ])

    response = final_prompt.invoke({
        "query": query,
        "knowledge": knowledge
    })

    return response.content

💡 为什么需要精炼？

网络搜索返回的文本通常包含大量无关内容（广告、导航、重复信息）。直接使用会浪费 LLM 的上下文窗口，并可能引入噪声。精炼步骤将信息压缩为高密度要点，显著提升生成质量。

9. 优势与局限

✅ 优势

  • 自适应质量把控：不盲目信任检索结果，主动评估信息质量
  • 多源信息融合：本地知识库 + 网络搜索互补，覆盖面更广
  • 减少幻觉：丢弃不相关文档，降低基于噪声生成错误回答的风险
  • 知识时效性：当本地知识不足时，可通过网络搜索获取最新信息
  • 透明决策：评分和路径选择可追踪、可调试

⚠️ 局限

  • 延迟增加：评估 + 搜索 + 精炼带来额外延迟（可能增加 2-5 秒）
  • 成本上升：每次请求需要多次 LLM 调用（评估、重写、精炼、生成）
  • 评估器依赖：决策质量取决于评估器的准确性，评估错误会导致错误路径选择
  • 网络搜索不稳定：DuckDuckGo 等搜索引擎可能返回低质量结果或被限流
  • 阈值敏感：0.3 和 0.7 的阈值可能需要针对不同场景调优
⚠️ 实践建议

CRAG 适合对回答质量要求高、可以接受一定延迟的场景（如客服系统、知识问答）。对于实时性要求极高的场景（如聊天机器人），可以考虑简化评估流程或使用缓存策略。

10. 总结与展望

Corrective RAG（CRAG）为传统 RAG 管道引入了关键的自我纠正能力。通过三个核心机制——相关性评估、动态路径选择和知识精炼——CRAG 将 RAG 从"被动检索"升级为"主动判断"。
